正文

群里有人扔了一句：「周五晚一条竖屏，素材就八段，谁来剪？」剪映开着，时间线拖得手腕酸；旁边同事说「用 Remotion 写啊，可复用」——可那条片子今晚就要，React 时间线今晚写不完。

这时候有人甩了个仓库：Concat，口号是开源 CapCut，还带 JSON-RPC 和给 agent 用的 MCP。我没急着吹，先问自己一句——它能不能少点鼠标，把一条竖屏脚本吐出来？

- - -

三条路，别混着比

短视频出片，我身边常见三条路：

剪映手动——上手最快，模板多，适合「今晚就要好看」。代价是产能靠人手，版本难 diff，账号和云空间习惯也重。

Remotion 代码出片——时间线进仓库，PR 能审，适合品牌片、讲解屏、要反复改版的片子。代价是你得会写、肯养工程。

Concat——本机 Rust 引擎，声称对标 CapCut 那套剪、字幕、导出；另外多了一刀：脚本和 agent 也能剪。许可证是 AGPL，这点后面单说。

图：剪映手搓 · Remotion 代码 · Concat 脚本/AGPL，先分清再选型

本篇只测一件事：用脚本把示例竖屏素材剪进时间线、叠一行标题、导出 1080×1920。自动字幕、克隆音色、抠图我这次没开——那些是下一层能力，别和「能不能脚本出片」搅在一起。

朋友听完还问：那跟「让大模型直接写一段 ffmpeg」有啥不一样？不一样在时间线状态。Concat 把工程、媒体、夹子、导出都收进同一套 API，agent 能读回当前时间线再改；纯 ffmpeg 命令拼来拼去，缺的是可回放的编辑状态。Remotion 也有状态，但它住在 React 组件树里——你得养工程。Concat 更像「本机剪辑器开了后门给脚本」。

仓库一手：星数、版本、协议

仓库在 GitHub 的 jub0t/Concat。我查的一手数（2026-10-22）：大约 1.05 万星、一千二百多 fork，主语言 Rust，许可证 AGPL-3.0。官方说法很直：免费、本地、跨平台，对标大家打开剪映常干的那些事；同时内置 MCP，脚本走 JSON-RPC。

版本上要记一笔：源码构建的 concat-cli 回报 0.2.8；我下的 Linux AppImage 和 Windows 安装包是 0.2.7。beta 阶段，发行包和源码 CLI 能力不是同一张脸——后面踩坑会碰到。

AGPL 这条红线先划清：自己本机剪、脚本批处理，通常还好；若改完当在线服务对外提供，一般要公开对应源码。短视频工作室自用和 SaaS 化，不是一回事。

环境：Linux 源码 CLI + Windows 安装版

我在 Linux 上从源码编出 concat-cli，独立工程放在 /home/laoli/laoli-concat-demo/，素材、工程、导出分开，不碰日常工作区。Windows 那边装了官方包，独立目录 C:\Users\laoli\projects\laoli-demo-concat-opensource-capcut\，先核版本。

图：concat-cli api 问 version，回报 concat 0.2.8、apiVersion 0.2

图：Windows 安装版 concat --version → 0.2.7

卡点要直说。发行版 GUI 二进制的命令行很瘦，常见只有 version / smoke / project；我这次完整的 JSON-RPC 流水线，是靠源码里的 concat-cli api（标准输入一行一条请求）。想接 Claude 一类 agent，官方文档写的是 concat --mcp。别假定「装好安装包 = 立刻有完整脚本面」。

MCP 文档里还分两种姿态：窗口开着、走 Automation 令牌的 window；以及引擎自己跑、不必开窗的 headless。默认 auto。agent 写入范围默认在用户主目录下，可用环境变量放开根目录。这些细节不炫技，但决定你能不能把 Concat 塞进现有 agent 流水线，而不是只当又一个下载安装包。

图：无显示环境跑 AppImage 会卡在窗口；无 GPU 时合成走 CPU——和 headless 导出是两条路

【广告位1】

最小竖屏：四步 JSON-RPC

示例素材是一条 8 秒竖屏：1080×1920、h264、25 帧、带单声道音轨。先 probe，确认引擎认得出文件。

图：probe 示例竖屏素材，时长与分辨率一次报清

接着按官方 API 语义走四步：

1. project.create——竖屏工程，宽 1080、高 1920、时间基 30/1。
2. media.import——把示例成片拖进媒体库。
3. edit.apply——视频轨铺满；文字轨从 0.5 秒起叠三秒标题「Concat demo」。
4. export.start——指定输出路径，等 progress，直到 export.done。

图：创建 / import / edit 的请求摘要，时间线状态可回读

请求都是一行一个 JSON。agent 要接的话，语义和 MCP 工具表是对齐的：建项目、导入、改夹子、导出、甚至拉一帧预览。本篇我用手写 JSON-RPC 跑通，证明不必开编辑器窗口也能出片。

实操手感：进度事件会一路推 export.progress（渲染帧 → 混音 → mux），最后一条 export.done 带上输出路径和宽高。脚本侧不用猜「好了没」——事件流本身就是验收凭证。我把请求和回执都落进了本篇 outputs，方便以后对照版本回归。

成片落盘：1080×1920，大约十秒

跑通了。export.done 回报输出 /home/laoli/laoli-concat-demo/exports/reel-vertical.mp4，宽高 1080×1920。再 probe 成片：h264 · 30fps · 8.000 秒 · aac 48kHz 双声道，体积大约 229KB。本机没有独显，合成走 CPU（lavapipe），墙钟大约 10.2 秒——八秒片子、加一行字，这个速度够日常脚本批处理。

图：export.done 与成片 probe，竖屏规格对得上

图：成片关键帧（标题区），示例工程名 laoli demo reel

不足也得直说：文字样式、特效库、磁吸时间线这些「剪映味」的东西，我这次几乎没碰；Windows 安装版也没有再复跑同一套 api 子命令——完整脚本链路目前以 Linux 源码 CLI 为准。beta 边缘还在，别把首发体验当成剪映替代品的完整体检表。

【广告位2】

对照一页：成本、可控、协议

成本感。剪映：时间成本在人手，钱成本在会员/云。Remotion：钱可以很低，人成本在工程。Concat：安装和编译有门槛，跑起来吃本机算力，没有「导出扣次数」那种墙。

可控。剪映难版本化。Remotion 最强——组件、props、CI。Concat 居中：JSON 请求可进仓库、可回放，但生态和类型提示还不如 Remotion 熟；agent 经 MCP 改时间线，适合「批量换标题/换素材」，不适合幻想它替你做导演。

协议。Remotion 常见 MIT 系，改起来心里踏实。Concat 是 AGPL——自用脚本友好，做成对外剪辑 SaaS 要先过合规。剪映则是产品条款和账号体系，不是开源协议问题。

再补一句成本账。这次八秒竖屏、本机无独显，导出大约十秒墙钟，电费可忽略；真正贵的是把脚本写稳、把素材路径和工程约定立住。剪映省的是学习成本，花的是重复劳动。Remotion 省的是长期改版，花的是工程启动。Concat 省的是「既要脚本又要时间线」，花的是 beta 毛边和协议注意力。三角关系摆清楚，比争「谁替代谁」有用。

谁适合上，谁先别上

适合：已经有素材管线、想让 agent/脚本批量换字换片、能接受本机编译或跟上 beta、业务是自用而非对外托管编辑器的人。

先别上：今晚就要一条爆款模板风的——回去打开剪映更快；要强设计系统、组件化讲解屏的——Remotion 仍更顺；计划把改过的引擎挂公网当服务卖的——先把 AGPL 问清楚。

一句话收束

Concat 不是来「消灭剪映」的，也不是 Remotion 的换皮。它卡在一个很具体的缺口：本机、可脚本、还能给 agent 握手。我这边最小竖屏链路已经跑通；发行版和源码 CLI 的差距、AGPL、以及 beta 毛边，都还在。先当工具箱多的那一层，别当信仰。
