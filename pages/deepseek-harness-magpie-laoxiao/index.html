正文

打开桌面，点进 DeepSeek Harness。左侧工作区还在，输入框也亮着——可一问模型，回答却像在绕远路：不是你今晚想用的那条通路。

今晚就办一件事：把桌面版 DeepSeek Harness 接到本机 Magpie，并指定已经实测过的模型 laoxiao/gemini-3.8-flash-high。步骤不长，但有一处很容易漏——漏了你会以为「命令写了却没生效」。

 

—先确认 Magpie 在跑—

打开终端。路径我写成读者友好的 C:\Users\laoli——你本机换成自己的用户目录即可。先看 Magpie 认不认本机这些客户端：

magpie ls
magpie providers

核对两件事。第一：列表里有没有 DeepSeek Harness 这一行。第二：供应商里有没有 Laoxiao（或你自己加好的 Laoxiao custom）。Magpie 本机网关地址记一下：http://127.0.0.1:3425/v1。网关没开，后面改配置等于空转。

图：magpie ls 现场。红线那行是 DeepSeek Harness，后面跟的是它当前指向的模型。

现场口令：先看 ls，再动手改。不知道现状，就不知道改完有没有真的跳过去。

【广告位1】

 

—测通 Laoxiao，再改 DSH 默认模型—

下一步不急着开聊天。先测供应商，确认 Laoxiao 这条线本身活着：

magpie provider test laoxiao

我这边跑完，看到的是两条绿勾：chat 通路过、gemini 通路过。你照做时也盯这两行——都是 ✓，再往下写 DSH。

图：provider test laoxiao。chat 与 gemini 都打勾，才进入下一步。

测通路过了，把 DeepSeek Harness 的默认模型指过去。模型名必须原样写：laoxiao/gemini-3.8-flash-high。Magpie 侧展示时可能带前缀，变成 magpie/laoxiao/gemini-3.8-flash-high——同一条模型，别被前缀吓到。

magpie models dsh
magpie dsh laoxiao/gemini-3.8-flash-high
magpie dsh

成功时会出现类似提示：✓ DeepSeek Harness model magpie/laoxiao/gemini-3.8-flash-high。再用 magpie dsh 回看一眼，确认还停在这条模型上。这一步 Magpie 会写进 DeepSeek Harness 的配置补丁（桌面与 web 两套 profile 都会落到 C:\Users\laoli\.dsh\profiles\ 下对应的 cordis.patch.yml），并把 Magpie 写成 provider，baseURL 指向 http://127.0.0.1:3425/v1。

图：magpie dsh 查询与写入。绿勾那行就是默认模型已经落到 Magpie/Laoxiao。

 

—打开 Magpie 路由页，核对箭头—

命令行说改完了，我仍习惯打开 Magpie 窗口再核一次。点到 模型 → 路由。现场应能看到：左侧 DeepSeek Harness 卡片挂着 laoxiao/gemini-3.8-…，右侧指向本机 127.0.0.1:3425。供应商状态里 Laoxiao 为启用。

图：红框里是 DSH → Magpie 网关。模型名与 3425 端口都要对上。

再切到 模型 → 供应商，确认 Laoxiao 还在列表里、没有被关掉。别的供应商你有你的，今晚只盯这一条。

图：红框对准 Laoxiao 供应商。其余条目已省略，避免干扰。

验收一句：路由页能画到 「DeepSeek Harness → 127.0.0.1:3425」，且模型名前缀对得上 laoxiao。对不上，先别开聊，回头重跑 magpie dsh laoxiao/gemini-3.8-flash-high。

 

—新开一个会话，旧会话不会自动跳—

回到 DeepSeek Harness。点 新会话。这一步不是仪式，是硬规矩：新会话才吃刚写进配置的默认模型；旧会话会继续握着自己当时的模型。如果你还停在改配置之前的那个对话里发消息，看起来就像「magpie dsh 白跑了」。

图：新会话主区。改完模型后来这里开聊；旧窗口要用 /model 或界面按钮再切一次。

旧会话想继续用？两条路：对话里敲 /model，或点输入框旁边的模型按钮，手动切到 laoxiao/gemini-3.8-flash-high（或带 magpie/ 前缀的同名项）。我自己的习惯更简单——配置类改动，直接新开一扇，少扯皮。

通路自检我用 Magpie 网关做过一次端到端：往 /v1/chat/completions 发请求，model 填 laoxiao/gemini-3.8-flash-high，回包里能看到预期内容。你今晚若只求「能在 DSH 里正常聊」，新会话里发一句短问题，看回复是否顺畅即可。若 Magpie 提示 Web search 还没配搜索源——先忽略，跟本次接线无关，不挡聊天主路径。

【广告位2】

 

—容易漏的三处—

  1. Magpie 网关没开。桌面版 DSH 走的是本机 127.0.0.1:3425。Magpie 退出了，聊天会直接断粮。改完配置后也别随手把 Magpie 关掉。
  2. 旧会话没切模型。默认模型只作用于之后新建的会话。旧的要 /model 或界面切换，否则你核对的是「旧世界」。
  3. 模型名写飘。必须原样：laoxiao/gemini-3.8-flash-high。少一段、多空格、大小写乱改，都会指到别处。

停止条件也说清：供应商 test 不过，就不要硬改 DSH；路由页对不上箭头，就不要急着判断「模型不行」——多半是网关或旧会话问题。

 

—你今晚就能做的—

  1. 确认 Magpie 在跑，终端执行 magpie ls 与 magpie providers。
  2. 执行 magpie provider test laoxiao，两条通路都要 ✓。
  3. 执行 magpie dsh laoxiao/gemini-3.8-flash-high，再用 magpie dsh 回看。
  4. 打开 Magpie「路由」页，核对 DeepSeek Harness → 127.0.0.1:3425。
  5. 回到 DSH 新开会话再聊；旧会话记得手动切模型。

敢动手，是因为步骤短、命令可复制、验收点清楚；有底气，是因为你知道旧会话不会魔法跳转、网关必须亮着。今晚把线接上，明天才轮得到比模型谁更聪明——线都没通，比来比去都是空响。
