【公众号账号】

一条 magpie dsh 敲完，Magpie 路由页上的箭头已经指向 127.0.0.1:3425——DeepSeek Harness 那边，却还在旧会话里握着旧模型。

不是命令白跑了。是验收方式错了：配置写进的是新默认，旧会话不会自动跟着跳。带着「为什么验收会错」往下看——后面把线接上，并把两处验收点说清楚。

这是接线教程，不是换供应商广告。示例供应商 id 写成 laoli，模型写成 laoli/gemini-3.8-flash-high——换成你 Magpie「供应商」列表里的真实 id 即可。

 

—两个常见卡点—

卡点一：默认模型对不上想用的通路。桌面版 DeepSeek Harness 打开了，输入框也亮着。发一句，走的却不是今晚指定的供应商或模型。改配置、重启、再聊，现象还在——多半不是模型本身，是线没接到你以为的那一端。

卡点二：供应商一多，箭头指哪不清楚。Magpie 里挂着好几家，DSH 与其他客户端各自记一套。界面上看似选中了 A，实际请求仍可能走 B。这时候别急着翻配置文件，先把「DSH 只认 Magpie」这条主线接上。

问题往往不在模型聪不聪明，而在线有没有接到你以为的那一端。

 

—一个方案：Magpie 当路由器，DSH 只认它—

思路很简单：让 Magpie 做本机网关，地址固定在 http://127.0.0.1:3425/v1。DeepSeek Harness 的默认模型，统一写成走 Magpie 的那条——示例就是 laoli/gemini-3.8-flash-high。以后换供应商、换模型，优先在 Magpie 侧改；DSH 这边少来回拧。

那接完到底长什么样？别急着敲命令——先看结果图。箭头对了，后面每一步都是在把它做出来。

图：接完后的路由主卡。DeepSeek Harness → Magpie 网关 127.0.0.1:3425，模型前缀对得上 laoli。

记住这个：验收不是「能不能聊两句」，而是路由箭头有没有钉到本机 3425。箭头不对，先别开始骂模型。

【广告位1】

 

—第一步：确认 Magpie 在跑、能看见 DSH—

先别改默认模型。先确认两件事：Magpie 认不认本机这些客户端；供应商列表里有没有你要用的那条。路径我写成 C:\Users\laoli——你本机换成自己的用户目录即可。

magpie ls
magpie providers

盯两行就够。第一，列表里有没有 DeepSeek Harness；第二，供应商里有没有示例条目（文中写作 Laoli / id laoli）。网关记死：http://127.0.0.1:3425/v1。Magpie 窗口都关了还敲命令，等于空转。

图：magpie ls。高亮那行是 DeepSeek Harness，后面跟的是它当前指向的模型。

看到 DSH 这一行了？好。下一步不是立刻改模型——先证明供应商这条线本身活着。测不通就硬写配置，等于给自己挖坑。

 

—第二步：测通 laoli 供应商—

一条命令，看 chat 和 gemini 两条通路能不能打勾。示例 id 是 laoli；你换成自己的真实供应商 id。

magpie provider test laoli

我这边是两条绿勾：chat 过、gemini 过。你照做时也盯这两行——都是 ✓，再往下写。失败了？先查密钥和网络，别急着怪 DeepSeek Harness。

图：provider test laoli。chat 与 gemini 都打勾，才进入下一步。

 

—第三步：一条 magpie dsh，写入默认模型—

现在才改默认。把 DeepSeek Harness 指到 laoli/gemini-3.8-flash-high。Magpie 侧展示时可能带前缀，变成 magpie/laoli/gemini-3.8-flash-high——同一条模型，别被前缀吓到。

magpie models dsh
magpie dsh laoli/gemini-3.8-flash-high
magpie dsh

成功时会出现类似提示：✓ DeepSeek Harness model magpie/laoli/gemini-3.8-flash-high。再用 magpie dsh 回看一眼。这一步会写进桌面与 web 两套 profile 的 C:\Users\laoli\.dsh\profiles\*\cordis.patch.yml，并把 Magpie 写成 provider，baseURL 指向 http://127.0.0.1:3425/v1。

图：magpie dsh 查询与写入。绿勾那行就是默认模型已经落到 Magpie / Laoli。

暂停一下。前三步做完了什么？确认客户端在列表里 → 测通供应商 → 把默认模型写进 DSH 配置。线已经接到 Magpie 这一端了。还差两件事：眼睛核对箭头，以及用对的会话去聊。

 

—第四步：路由页再对一次箭头—

命令行说改完了，打开 Magpie 窗口核一次。点 模型 → 路由，对照开篇那张目标图；再切 模型 → 供应商，确认 Laoli 还在且启用。

图：红框对准 Laoli 供应商。其余条目已省略，避免干扰。

验收一句：路由能画到「DeepSeek Harness → 127.0.0.1:3425」，且模型名前缀对得上 laoli。对不上，先别开聊，回头重跑 magpie dsh laoli/gemini-3.8-flash-high。

 

—第五步：新开会话验收——旧会话是坑—

回到 DeepSeek Harness，点 新会话 再聊。这不是仪式，是硬规矩：新会话才吃刚写进配置的默认模型；旧会话会继续握着自己当时的模型。还停在改配置前的那个对话里发消息，看起来就像「magpie dsh 白跑了」——开篇我说的那个坑，就是这儿。

图：新会话主区。改完模型后来这里开聊；旧窗口要用 /model 或界面按钮再切一次。

旧会话还想继续用？两条路：对话里敲 /model，或点输入框旁的模型按钮，手动切到 laoli/gemini-3.8-flash-high（或带 magpie/ 前缀的同名项）。我自己更省事——配置类改动，直接新开一扇。

今晚若只求「能在 DSH 里正常聊」，新会话发一句短问题即可。若 Magpie 提示 Web search 还没配搜索源——先忽略，不挡聊天主路径。

【广告位2】

 

—容易漏的边界—

  1. Magpie 网关没开。桌面版 DSH 走本机 127.0.0.1:3425。Magpie 退出了，聊天直接断粮。改完也别随手关。
  2. 旧会话没切模型。默认模型只作用于之后新建的会话。旧的要 /model 或界面切换。
  3. 模型名 / 供应商 id 写飘。示例必须原样：laoli/gemini-3.8-flash-high；把 laoli 换成你自己的供应商 id 时，别少段、别多空格。

停止条件说清：供应商 test 不过，就不要硬改 DSH；路由页对不上箭头，就不要急着判断「模型不行」——多半是网关或旧会话问题。能做的是把线接上并指定模型；不能做的是指望旧会话自动跳过去。

 

—你今晚就能做的—

  1. 确认 Magpie 在跑，终端执行 magpie ls 与 magpie providers。
  2. 执行 magpie provider test laoli（换成你的供应商 id），两条通路都要 ✓。
  3. 执行 magpie dsh laoli/gemini-3.8-flash-high，再用 magpie dsh 回看。
  4. 打开 Magpie「路由」页，核对 DeepSeek Harness → 127.0.0.1:3425。
  5. 回到 DSH 新开会话再聊；旧会话记得手动切模型。

 

—说回开头那个坑—

箭头已经指向 3425，旧会话却还握着旧模型——不是 Magpie 骗人，是验收点没选对。卡点一（默认对不上）靠一条 magpie dsh 写进默认；卡点二（供应商太多）靠「DSH 只认 Magpie」收束。有底气，是因为验收点清楚：箭头在不在、新旧会话吃不吃配置、网关亮不亮。

今晚把线接上。明天再比模型谁更聪明——线都没通，比来比去都是空响。下期见。
