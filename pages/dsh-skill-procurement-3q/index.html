【公众号账号】

做采购询价最怕口径每次飘：上回问了交期，这回只聊单价；账期质保又忘了。群里一吵，供应商回复也对不齐。今晚不换采购系统，只在 DeepSeek / DeepSeek Harness 里用 Skills 把三问钉死，让 AI办公复跑仍同序。

你会问的大概就这几个——下面按问答写。

 

—Skills 是干什么的？—

短答：把「每次必须问什么」写成可复用说明书，会话按它执行。不是又一个聊天语气插件，是口径锁。采购询价这种重复话术，最适合。

图：skills/procurement-3q/SKILL.md——固定三问写在技能文件里。

你可以把它理解成「询价检查清单的可执行版」：人写口径，DeepSeek Harness 按口径提问与标缺口。采购询价一多，口头传统就会丢字段；写进 Skill 以后，新人接力也不容易漏问。

和普通提示词的差别在于：Skill 可复用、可放进仓库、可在多会话引用；你不用每次把三问从头打一遍。AI办公要的就是这种少重复、少漂移。

【广告位1】

 

—三问具体锁哪三条？—

短答：含税单价+MOQ；交期+逾期责任；账期/付款+质保。

  1. 含税单价与最小起订量（MOQ）——只问单价不够。
  2. 交期（工作日）与逾期责任——没有责任条款，交期是空头支票。
  3. 账期 / 付款方式与质保期——财务和品质两边都要落字。
# procurement-3q
## 固定三问（每次询价必须覆盖）
1. 含税单价与最小起订量（MOQ）
2. 交期（工作日）与逾期责任
3. 账期 / 付款方式与质保期
## 输出格式
- 供应商:
- 三问答复:
- 缺口:
- 风险一句:

 

—会话里怎么调用？同单复跑稳不稳？—

短答：提示词点名按该 Skill 审 brief；复跑看三问顺序与字段名是否不变。

按 skills/procurement-3q/SKILL.md 的固定三问，审这份 rfq_brief。
输出：供应商待问清单 + 三问缺口；不要改三问口径。

图：本机真跑产物用 VS Code 打开；红框罩固定三问与待问清单。

示例 brief 有规格与月量，缺 MOQ、交期、账期、质保——模型应列缺口，而不是假装供应商已答。

图：固定三问验收；红框三行口径，复跑仍同序。

【广告位2】

 

—不适合什么场景？—

短答：合同谈判全文、法务条款对抗，别指望一条 Skill 包办。Skills 管「每次必问」；复杂博弈还是人来。停手条件：模型开始改写三问顺序或合并字段——打断，回到 SKILL.md。

同单复跑时，把输出并排对比：三问标题是否仍是同一组汉字与同一顺序。顺序一变，缺口表就没法跨同事对齐——采购询价口径锁的意义就没了。

  • 适合：重复询价、多人接力、要统一话术。
  • 不适合：把 Skill 当合同模板自动生成盖章件。
  • 边界：桌面 Agent 锁口径，不替代 SRM。

 

—最后—

采购询价口径飘，就用 DeepSeek Skills 锁三问；AI办公复跑看顺序稳不稳，不看辞藻漂不漂亮。

适合供应链询价高频岗；法律审查另走流程。
