【公众号账号】

做 采购询价 最怕口径每次飘：上回问了交期，这回只聊单价。今晚不换采购系统，只在 DeepSeek Harness 桌面里用 Skills 把三问钉死。

卡点很具体：询价单只有品名规格月量交货地，规格验收、交期违约、价格口径常年待补。任务就一件——按三问审查并给出可粘回的补句。

下面按普通人跟做写：材料认清 → 桌面启用/粘贴 → 看三问是否待补。

 

—材料放桌面—

示例放在桌面 采购询价示例：一份 RFQ 简报，外加 Skills 说明。三问固定为规格与验收、交期与违约、价格口径。

  1. rfq_brief.txt：品名 / 规格 / 月量 / 交货地
  2. SKILL-procurement-3q：三问口径说明
  3. 文件夹放桌面，名字就叫「采购询价示例」

红框：桌面「采购询价示例」RFQ 与 Skills 说明。

材料认清之后，先别急着点发送。桌面版跟命令行最大的差别，就是你能看见输入框、发送键和回复区——照着点就行，像教同事用办公软件。跟做前先确认 DeepSeek Harness 桌面窗能打开、能新建会话；提示词整段复制即可，不用自己改写口径。

【广告位1】

 

—桌面里怎么点—

打开 DSH 桌面版 → 点 新会话 → 若客户端有 Skills 入口，先启用采购三问；没有也能直接粘贴下面提示词，把口径写死在对话里。

请读取桌面上的「采购询价示例」文件夹（含 RFQ 与 Skills 说明）。

任务：按采购三问口径审查这份询价材料。
三问固定为：
1）规格与验收是否写清？
2）交期与违约是否可执行？
3）价格口径（含税/未税/运费）是否完整？
输出：三问逐条「通过／待补」+ 依据摘录；末尾给一版可粘回询价单的补句建议。
只许引用原文，禁止编造。用 Markdown 直接回复。

三问顺序 不要让模型合并或改写；合并了就打断，回到固定三问。

红框：桌面主区——采购三问提示词已粘贴。

 

—产物怎么验收—

桌面真跑后：三问全部标成 待补——这份示例 RFQ 本来就没写验收、违约和含税口径。补句建议只能要求对方补齐，不能自拟价格天数。

红框：桌面主区三问「待补」与补句建议。

验收时只盯三问状态列：是不是都标成「待补」。补句里若出现原文没有的价格、天数、比例，一律删掉——只能要求对方补齐，不能自拟数。桌面主区能看见待补结论和补句，这篇才算跟做完成。

【广告位2】

这一步的情绪很实在：表摊开了，心里有底了，剩下的是人核与回业务系统，不是继续跟模型磨洋工。桌面会话到验收为止，改原表还是回业务系统，都是人的事。

 

—坑与何时停—

  • 模型改写三问顺序或合并字段 → 打断，回到固定三问
  • 补句里填入原文没有的价格/天数 → 删掉，只留占位要求
  • 把 Skill 当合同自动盖章 → 停，那是法务的事

 

—最后—

普通人跟做时记住：桌面主区能看见的表，才是验收对象；示例公司数据只用来对照步骤，换成你自己的材料时，提示词里的文件夹名一并改掉。路径对外只写桌面文件夹名。

采购询价口径飘，就用 DeepSeek Skills 在桌面锁三问；AI办公 复跑看顺序稳不稳，不看辞藻漂不漂亮。
