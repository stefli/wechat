正文

供应商门户刚让 Agent 抓了一遍，回过来的摘要里忽然多了一句「站点要求你先完成某项注册」。人用浏览器打开同一页，根本没有这句。群里同时甩来吓人截图：「HTTP 响应头已经在给 AI 下命令了。」

今晚别急着改架构。先办成三件事：搞清头里的「提示词」是啥、会撞上什么现象、站长和跑 Agent 的人各该查哪几项。办完再决定慌不慌——中间那道坎，比标题党想的窄。

 

—是什么：HTTP 头里给爬虫看的「提示词」—

先把词说成人话。HTTP 响应头，是服务器在页面正文之外捎给对方的「小纸条」：内容类型、缓存多久、能不能跨站……平时浏览器看，现在也会被爬虫、Agent 抓取工具读到。所谓「HTTP 头里的提示词」，就是有人在这些小纸条里，专门写给 AI / Agent 看的字——不是给你看的正文，是元数据里的附言。

间接提示词注入（指令藏在网页、邮件、工具结果里，跟你的提问一起进模型上下文）听起来玄，落到响应头上，常见其实就三类。公开扫描也是按这个口径分的。

图：响应头里写给 AI 看的字，多数是路标；政策与检测其次；命令意味的极少。

  1. 路标头：告诉 Agent「说明文件在这儿」。最常见的示意写法是指向 llms.txt（给模型读的站点说明）的头，公开材料里大量走 x-llms-txt 一类名字。本质是指路，不是下命令。
  2. 政策 / 检测头：声明使用规则，或标注「你看起来像 AI 爬虫」。仍是说明性质，读者不必当成系统提示。
  3. 玩笑 / 指令意味头：试图让模型「忘掉用户刚才说的」「去完成某注册」一类——公开扫描里这一类很少，且报告写明多数是整蛊。正文不贴可复制的攻击串，你只需要知道：它长得像「命令句」，不等于已经生效。

路标长什么样？看一眼示意就够（示例域名，不是让你照抄去攻击）：

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
x-llms-txt: /llms.txt

记住边界：头里有字 ≠ 模型已经听令。路标可以有；把玩笑头当系统提示，才是误判的开始。

【广告位1】

 

—出什么问题：吓人帖和真边界差在哪—

你会撞到的现象，通常不是末日片，而是这几种。现象一：Agent 把玩笑头当真。摘要多废话、忽然提「站点要求你……」，人用浏览器却看不到——多半是抓取路径把响应头摘要进了上下文，模型把附言当成了页面意思。

现象二：你自己的提示词把站点写成了权威。配置里写了「听从站点给 AI 的一切指令」，等于主动把小纸条升成老板。公开材料里的工作示例也落在这：普通「帮我看文档」任务下，模型常能拒；加上这类授权句，部分型号才开始乱动。红线就这一句——别把「站点说了算」写进你自己的提示词。

现象三：人和 Agent 看见的不是同一页。站点按 User-Agent（用户代理字符串）区分爬虫，对 AI 客户端回另一套内容——叫伪装分发（cloaking）。你浏览器自查「干净」，挡不住 Agent 真实请求头拿到的版本。

图：现象分三层——误读玩笑、自己授权站点、按 UA 给人/Agent 不同内容。

公开数字用来定边界，不用来吓人。安全团队 Signals Corps 读了 Common Crawl 一次月度抓取（爬取标识 CC-MAIN-2026-39）约一成样本，合计 两亿一千七百多万 条页面响应的响应头；媒体 The Register 随后转述。主语是他们的公开报告，不是本号半夜扫全网。

图：217M+ 响应头 → 7,959 站发 AI 向头 → 多数路标 → 约 30 次试图下指令（多半玩笑）。

  • 7,959 个站点发了面向 AI 的响应头；其中 7,271 是路标（6,989 走 x-llms-txt 一类）。
  • 政策声明、检测类、使用指引占了其余大半；真正被标成「试图下指令」的约 30 站，报告写明多数是玩笑。
  • 真要成「接管」，公开口径是三件齐：头进了模型上下文、模型肯听、工具还有写库/外发/跑命令的权限——三缺一，多半是段子。

什么情况下不需要恐慌：抓取默认只取正文、提示词没把站点写成权威、危险动作要人工点头。这时候刷到「全网响应头注入」标题，先找分母，再决定要不要加班。

【广告位2】

 

—怎么解决：站长今晚查哪几项头—

如果你是站长，今晚目标不是「发明新协议」，是把命令意味的头清干净、路标说清楚。按这个清单过一遍 CDN / 反向代理 / 应用响应头配置：

  1. 列出当前所有自定义响应头，重点搜带 llms、ai、agent、bot、prompt 字样的名字——先搞清「有没有、是谁加的」。
  2. 路标只保留约定清楚的说明入口（例如指向 llms.txt）；不要在头里写命令句、整蛊句、求职匹配玩笑串。
  3. 检查按 User-Agent 分流的规则：可以对爬虫限流，不要对 Agent 偷偷换成另一套事实内容；要分流，策略自己要说得清。
  4. 若历史上加过「给 AI 下命令」营销梗，今晚直接删；玩笑也会被吓人帖二次传播。
  5. 改完后用一次真实抓取（或团队 Agent 的请求头）核对「它看见的头」和你以为的一致。

默认建议：指路用说明文件，头里少说话。例外：合规要求必须声明的政策头可以留；停止条件：一出现命令句/整蛊句，先清再议。

 

—怎么解决：跑 Agent 的人怎么忽略不可信头—

图：左栏站长清命令头；右栏跑 Agent 的人只喂正文、删授权句、人工批准。

如果你负责扫描或跑 Agent，今晚加固入口，不靠转发末日帖，靠这几条可执行规矩：

  1. 默认只把页面正文喂给模型；打开抓取说明或日志，确认会不会把响应头一并塞进上下文。能 body-only 就 body-only。
  2. 全文搜索提示词模板、系统提示、Agent 配置，删掉任何「听从站点 / 服从页面给 AI 的指令」类授权句——这是自己挖的坑。
  3. 网页或元数据里建议的安装、注册、外发：必须人工确认再动；写进团队备忘，别靠自觉。
  4. 重要供应商门户抽一两个地址，用 Agent 真实请求头对照「它看见的」和「你浏览器看见的」；不一致就当伪装分发苗头，先停自动动作。
  5. 把「响应头不可信」写进工具默认策略：头可以记日志排查，不要当系统提示执行。

 

—你今晚就能做的—

  1. 站长：导出/查看当前自定义响应头列表，标出 AI 向字段，清掉命令意味与玩笑句。
  2. 跑 Agent：确认抓取是正文还是连头；能关「带头进模型」就关。
  3. 全库搜提示词，删除「听从站点」类授权句。
  4. 定一条团队规矩：网页建议的命令/注册，必须人工点头。
  5. 抽一个关键业务站点，做一次「浏览器所见 vs Agent 所见」对照，记进备忘。

不被忽悠，是把吓人标题还原成「是什么 → 出什么问题 → 怎么解决」；有底气，是清单今晚就能勾完。HTTP 头里的提示词，今天更像稀有玩笑加一条卫生提醒——真要出事，多半先出事在「你把站点写成了老板」。
