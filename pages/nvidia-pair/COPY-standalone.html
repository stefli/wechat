正文

本机这块笔记本显卡，显存大约就 8G。不是工作站，也不是机房那排绿灯。我想知道：NVIDIA 新出的 PAIR 1.0，能不能在这台 Windows 本机上，把本地推理先串起来——起码单机跑通，再谈局域网显卡池。

一句话新闻：NVIDIA PAIR 1.0 把多台机器上的本地推理引擎（Ollama、llama.cpp、LM Studio）收成一个池子，统一路由聊天请求。我这趟只验了单机 + 已有 Ollama。

— 本机环境 —

系统是 Windows。显卡：NVIDIA GeForce RTX 5060 Laptop，驱动里显存大约 8151 MiB（约 8G）。工作目录我写成虚拟路径：

C:\Users\laoli\projects\pair-test\

安装包是官方 Windows x64：

NVPAIR-Setup-1.0.0-x64.exe。跑起来的产品版本是 PAIR 1.0.0.85。本机本来就装着 Ollama 0.40.4，模型用现成的 qwen3:4b（大约 2.5GB）。

【广告位1】

— 安装：正式要管理员，我这趟先解压跑通 —

实话实说：官方静默安装命令

NVPAIR-Setup-1.0.0-x64.exe /S 在我这边被 UAC 拦住了——没点管理员同意，装不进 Program Files，开始菜单、防火墙规则那些也不会自动配好。

为了先把软件摸通，我用 7-Zip 把安装包解压到：

C:\Users\laoli\projects\pair-test\extracted-app\
然后直接跑 PAIR.exe

这能拉起界面和后台代理，但不等于正式安装。正式装还是得管理员点一次 Yes。别把“解压能跑”当成“装好了”。

— 引擎：接管本机 Ollama —

Overview：本机节点 LOCAL，Ollama 已打开；LM Studio / llama.cpp 仍是下载按钮（路径已虚化）

PAIR 认出了我本机已有的 Ollama，状态是已接管（adopted）。代理地址变成：

http://127.0.0.1:11435

原来的 Ollama 还占着 11434；PAIR 在 11435 上开了一层 OpenAI 兼容代理。模型就用磁盘上的

qwen3:4b。这一轮没有通过界面把 llama.cpp 装上——Overview 里仍是下载按钮，我留着以后手动点。

— 实测数字 —

Jobs：两次 qwen3:4b 已完成（冷启动一次、热一次）

经 PAIR 代理发聊天请求，HTTP 都是 200：

• 冷启动（模型刚加载）：大约 67.4 秒
• 热请求（模型已在显存里）：大约 34.5 秒

推理结束后看显存：大约 7.5–7.6 / 8.1 GB 在用。8G 卡跑 4B 级本地模型，压力是实打实的，但链路通了。

单机节点跑通后的 Overview（主机名已虚化为 LAOLI-PC）

【广告位2】

— 这趟踩过的坑 —

1. 正式安装要管理员。没过 UAC，就别指望 Program Files 那一套。
2. 解压能跑 ≠ 装好。快捷方式、防火墙、运行库自动装，解压路径都没有。
3. 多机还没验。PAIR 宣传的是局域网显卡池；我只有一台本。要串第二台，得同网段再装 PAIR，用 6 位 PIN 配对，两边引擎和模型 ID 还得对齐。
4. llama.cpp 这轮没装。界面有入口，我没点完；现成 Ollama 已经够验代理。
5. 冷启动六十多秒，多半是模型进显存；别拿热请求的体感去估第一次。

— 老李的判断 —

值得上手的地方：它不是又一个网页聊天框，而是本机/局域网推理的路由器。我这块约 8G 的 RTX 5060 Laptop，单机 + Ollama + qwen3:4b，经 PAIR 代理聊天是通的，Jobs 里也能看见跑完的任务。

要掂量的地方：1.0 很新；正式安装依赖 UAC；多机能力我还没亲手串；llama.cpp / LM Studio 要另装。显存紧的时候，别指望再塞更大的模型硬刚。

适合谁：家里或工位已经有 NVIDIA 本机、愿意本机跑 Ollama 的人。想一次点开就“多机显卡池”，先准备第二台电脑和同网段环境。

— 一句话总结 —

NVIDIA PAIR 1.0 我本机跑通了：Windows + RTX 5060（约 8G）+ Ollama 0.40.4 + qwen3:4b，经 11435 代理冷约 67 秒、热约 34 秒。解压能摸，正式装要管理员；多机和 llama.cpp 留待下一趟。
