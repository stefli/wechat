【公众号账号】

让助手搭页面，最常见的尴尬是按钮对不上。颜色、圆角、字号各写各的；同一套产品里的主按钮，隔一夜再生成，又换了一种样子。问题往往不在模型嘴碎，而在它手里没有一份能照着执行的设计规范。

今晚要办成的事很具体：把 Meta 开源的设计系统Astryx装到本机独立目录，让它先写出给 AI 助手看的规则，再在本地页面上跑出一颗官方主按钮。不是今晚就把完整后台交出去。

文档把它写成 fully customizable and agent ready。按下面顺序跟，先看本机到底能见到什么，再决定要不要把整页交给助手去搭。

—材料准备—

先把环境放齐，再开命令行：

  • 本机已能跑 npm / npx。官方文档要求 React 19 或更高，并安装 peer 依赖 @stylexjs/stylex。
  • 新建独立目录 /home/laoli/projects/laoli-demo-astryx，不要打开正在做的工程。先用 Vite 建一个 React 19 项目，再在该目录装 Astryx。用 Vite 的 React 模板在该目录建项即可；工程里还需要 React 19、Vite 和 @vitejs/plugin-react，具体补丁号会随发布变动，这里不写死。完整的 index.html、开发脚本、vite.config.ts 和入口文件，我会在后面「本机跑出『保存草稿』按钮」一节给出。
  • 准备一个浏览器，后面要看本机开发页。
  • 官方文档站是 astryx.atmeta.com；开源仓是 github.com/meta/astryx，许可 MIT，TypeScript。

材料齐了，先打开文档看清它怎么自称，再按官方命令安装。路径一直用上面这个独立目录即可。

【广告位1】

—先打开官网，看清它的主主张—

打开文档站首页，首屏就能看见Astryx的主主张：开源、可定制、面向 agent。当晚官网首屏标明 Currently in Beta，图上还可见 Built on React 19+ and StyleX。这是官网自己的说法，先记下，后面用本机最小演示去对照，不要一上来就按「已经能搭整站」来理解，也不要把今晚能跑出官方主按钮，理解成它已经稳定、可直接用于生产。

官网首页真屏（astryx.atmeta.com 首屏），不是本机演示。首屏标明 Currently in Beta。

首页下方还有组件、主题、示例入口。今晚不顺着这些入口把整站例子跑一遍，只把它当作对照材料。

—按官方命令安装到独立目录—

进入 /home/laoli/projects/laoli-demo-astryx，按官方 Install 文档安装核心包、主题、CLI，以及文档要求的 StyleX peer 依赖：

npm install @astryxdesign/core @stylexjs/stylex @astryxdesign/theme-neutral @astryxdesign/cli

我当晚装到的是 @astryxdesign/core@0.7.12、@astryxdesign/theme-neutral 和 @astryxdesign/cli@0.7.12。版本会随发布变动，这里只记录当晚实装结果，不把它写成永远不变的官方保证。

—执行 init，写出 AGENTS.md—

文档「Working with AI」写得很直接：安装 CLI 之后，执行 init，把给 AI 助手看的说明写进项目。官方示例是 npx @astryxdesign/cli init --features agents。我当晚在这个基础上加了 --agent cursor，命令如下：

npx @astryxdesign/cli init --features agents --agent cursor

官网文档真屏：Working with AI 写明 init 会生成给助手看的说明文件。不是本机终端。

命令跑完后，项目根目录里出现了 AGENTS.md。我没有用终端截图来顶替，那类画面容易挤乱，改把当晚文件里最要紧的几句摘在这里：

Astryx v0.7.12 · 174 components
CLI: run every command as `npx astryx <cmd>` (shown below as `astryx ...`).

SETUP (once, in app entry e.g. main.tsx) — without these, components render unstyled:
  import "@astryxdesign/core/reset.css";
  import "@astryxdesign/core/astryx.css";

先看两处。抬头的版本和组件数，是当晚这份说明自己写的；下面的 SETUP 是硬条件——不引入这两份官方 CSS，组件就会按未样式化来渲染。文件后半还有 astryx build、template、doctor 等工作流，那是给助手搭整页用的。我当晚没有顺着那条工作流去搭完整页面，只是先把规则落到项目里。

—本机跑出「保存草稿」按钮—

规则有了，下一步是亲手引入官方组件，看本机能不能见到一颗有样式的主按钮。前面说过，要先用 Vite 建好 React 19 项目，再在该目录装 Astryx。下面这几份是我当晚实际用到的文件，照着放到对应位置即可。

先看页面入口 index.html。标题写成「Astryx 最小演示」，页面里留一个 root 节点，再引入 src/main.tsx：

<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Astryx 最小演示</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>

开发服务器用的是 Vite。package.json 里当晚的 dev 脚本是：

"dev": "vite --host 127.0.0.1 --port 5173"

工程里还需要 React 19、Vite 和 @vitejs/plugin-react，具体补丁号会随发布变动，这里不写死。vite.config.ts 也要放进项目，否则执行 npm run dev 时仍可能断掉。当晚实用的配置如下：

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
export default defineConfig({
  plugins: [react()],
  server: { host: '127.0.0.1', port: 5173, strictPort: true },
});

入口文件 src/main.tsx 要写完整：用 StrictMode 和 createRoot 挂到 root，再使用 Theme、中性主题 neutralTheme，放一颗 Button，文案写成「保存草稿」，变体用 primary。关键是把官方样式引进来：

import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { Theme } from '@astryxdesign/core/theme';
import { neutralTheme } from '@astryxdesign/theme-neutral/built';
import { Button } from '@astryxdesign/core/Button';
import '@astryxdesign/core/reset.css';
import '@astryxdesign/core/astryx.css';
import '@astryxdesign/theme-neutral/theme.css';

function App() {
  return (
    <Theme theme={neutralTheme}>
      <main style={{ padding: 32, maxWidth: 640, fontFamily: 'system-ui, sans-serif' }}>
        <h1 style={{ margin: '0 0 8px', fontSize: 28 }}>Astryx 最小演示</h1>
        <p style={{ margin: '0 0 24px', color: '#475569' }}>用官方组件在本机跑通一颗主按钮。</p>
        <Button label="保存草稿" variant="primary" />
      </main>
    </Theme>
  );
}

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);

在该目录执行 npm run dev，开发服务器落在 127.0.0.1:5173。用浏览器打开后，我看到的是一颗深色圆角的「保存草稿」主按钮，不是没有样式的裸按钮。

本机最小演示真屏：地址栏是 127.0.0.1:5173，页面标题「Astryx 最小演示」，主按钮为官方样式的「保存草稿」。这不是已经搭好的完整产品。

所以你下次也可以先把验收钉在这一颗按钮上。按钮出来了，只能说明设计系统在本机能用；不能说明后台、列表、权限、整页模板都已经就绪。

—对照官网还能看到什么—

本机按钮跑通之后，再回到文档看 CLI 能做什么。官方 CLI 页写明可以查组件、查文档、列模板；页面上当晚还能看到 Install v0.7.12 这样的安装提示。图上可见示例是 component Button；我当晚在本机执行的是 component --list。

官网 CLI 文档真屏，不是本机终端。图上可见示例是 component Button；命令列表以当晚页面为准。

我当晚在本机执行了 component --list，CLI 给出 174 个组件；AGENTS.md 抬头也写了同一个数字。这是当晚文档和 CLI 给出的数字，发布更新后可能会变，不要把它抄成永恒不变的官方保证。

对照时还有两处必须说清。官网有 Sandbox，里面能看到许多组件和主题卡片——我没有把这些官方例子整站跑起来，所以不能写成「已经在本机复现了 Sandbox」。另外，我打开过官方 Storybook，左侧目录和管理器出来了，预览画布却一直转圈，组件预览没有出来。预览没出来，就不要写成已经看过组件。这两张转圈的画面我也不放进正文，以免扫读时被当成成功预览。

核验仓页时，star 数大约是 2.2 万。这个数字同样只是当晚看到的约数，用来判断项目热度，不是功能清单。

—怎么验收—

验收只对今晚真实做到的三件事。对照下面三条即可，不要自行加码成「完整后台已经跑通」。

  1. 装上并引入官方样式。核心包、主题和 CLI 已进独立目录；入口文件引入了 reset.css 和 astryx.css。
  2. 项目里写出了 AGENTS.md。能看到当晚版本、组件数，以及「不引入官方 CSS 则组件没有样式」这句说明。
  3. 本机看到「保存草稿」按钮。浏览器打开 127.0.0.1:5173，见到的是样式化的深色圆角主按钮，不是未样式化的裸按钮。

三条都满足，今晚的最小演示就算站住了。整页模板、业务表单、权限后台，都不在这份验收里。

【广告位2】

—我的经验教训—

第一件：AGENTS.md 把这句放在 SETUP 里，不是附注：不引入官方 CSS，组件就会没有样式。我当晚在入口里写上了 reset.css 和 astryx.css，本机才见到深色圆角的主按钮。你要是只看到一个没有圆角、没有主题色的裸按钮，先回头检查这两行引入，别急着怪组件本身。

第二件：开源设计系统能用，不等于开箱就是一套完整业务后台。官网卡片很多，CLI 也能列出一批组件，但这只说明零件和规则在。不要把开源设计系统理解成已经搭好完整业务后台。我当晚做到的是一颗官方按钮，加上一份写给助手的说明。整页交给助手按规范去搭，是下一步，不是今晚已经做完的事。

第三件：官方 Storybook 我打开过，侧栏出来了，预览却一直转圈。当时如果图省事把转圈画布贴出去，读者会以为组件预览已经见到。后来我选择不放那两张图，只在文字里交代边界。你要是也卡在预览转圈，停在「还没看到组件」即可，不要硬写成已经看过。

—最后—

结论钉在一句：今晚可以把 Astryx 装进独立目录，写出 AGENTS.md，并在本机跑出一颗官方样式的「保存草稿」按钮。规则已经在项目里，按钮也已经在浏览器里；这仍是最小演示，不是完整后台。组件数量以当晚文档和 CLI 给出的数字为准，不必写成不变的保证。

适合今晚就试的人：本机能跑 npm，想先让助手有一份可执行的设计规范，并亲眼见到官方按钮。不适合的预期：读完就等于已经用 Astryx 搭好业务后台，或把官方 Storybook 转圈画布当成组件预览成功。

供应链老登的 AI 江湖，专聊能上手的。下期见。
