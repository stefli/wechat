【公众号账号】

月底盯销售台账最烦的不是公式，是那几行「看起来不对」——数量突然翻倍、同月同 SKU 多出一笔。人肉扫表，眼一花就漏。今晚不换 ERP，只把表丢进 DeepSeek Harness，让这套 AI办公里的办公 Agent 先标异常、再算环比。

卡点很具体：表在桌面「销售台账示例」，打开了、筛选了，异常仍靠感觉。任务就一件——读 CSV、标异常行、给出区域金额环比，数字只许引用原表。

下面按现场顺序记：材料摊开 → 提示词 → 产物核对。不吹企业级风控，只写本机能复现的。

 

—先把销售台账摊开—

打开我的文档里的示例目录（正文路径按常见写法：桌面或我的文档下的「销售台账示例」）。表头是月份、区域、SKU、数量、金额。九月到十月都有；华北一条数量从 85 跳到 210，华东同月同 SKU 多出 qty=5。

图：销售台账示例整理前；浅红行为后续要对的跳升与疑似重复。

所以你照做时：先自己用眼睛瞄一眼可疑行，再让 DSH 出清单——方便对照，不是让模型替你签字。

【广告位1】

 

—提示词怎么写才不飘—

短句锁任务：读哪张表、什么叫异常、输出什么列。办公Agent 最怕「帮我看看有没有问题」这种空话——口径一飘，环比就会编。

读取桌面「销售台账示例」里的 sales_ledger_2026Q3Q4.csv。
标出异常行：数量环比>50%，或同月同SKU疑似重复。
再给出各区域金额环比%。
输出表：行号 / 异常类型 / 依据 / 环比。
数字只许引用原表；不要编造原表没有的行。

图：DeepSeek Harness 会话主区——提示词锁异常口径，回复先列跳升与疑似重复。

红线：不要让它「顺便优化」把疑似重复静默并进合计；环比分母必须说清是否含重复行。

 

—核对异常行与环比—

本机用 headless 同口径复跑过：华北 SKU-B07 数量 85→210，环比约 +147%；华东 SKU-A12 同月另有 qty=5，标成疑似重复。区域金额环比里，华北跟着跳；华东含不含重复会差出几个点——这正是人要拍板的地方。

图：异常行与环比验收表；红框罩住两条异常（跳升 + 疑似重复）。

  • 跳升类：看数量与金额是否同向；只数量跳、金额平，要怀疑单价或单位。
  • 重复类：同月同 SKU 多行，先标后人工删，别让模型直接改原表。
  • 新区域：无上月基数就写「新增」，别硬算无穷大环比。

【广告位2】

 

—边界：AI办公盯表，不替你盖章—

能做的是异常清单与环比草稿；不能做的是认定舞弊或自动改账。DeepSeek Harness 在这条链路上是办公Agent：加速扫表，不替代财务复核。

  1. 原表不动；输出另存「异常与环比」草稿。
  2. 环比口径写进提示词，复跑时别改阈值。
  3. 停手条件：模型开始补「合理原因」却给不出原表依据——打断，只留数字行。

 

—最后—

意图就一句：把销售台账推进 DeepSeek Harness，用 AI办公方式先标异常再算环比。本机复现过跳升与疑似重复两条；人负责拍板，Agent 负责别漏行。

适合月底要快速过表的人；不适合指望一键出审计结论的场景。下一篇若要对银行流水，口径同样是「差额显式列出」。
