正文

周五下班前，朋友在群里甩了句：「电脑上起了个小页面，手机同一 Wi‑Fi，地址栏敲局域网地址，居然开出来了。」

下一秒他又发语音：点「打开摄像头」，要么弹拒绝，要么按钮没反应。页面按钮还在，样式也正常——就差镜头那一下。

网页都开了，摄像头凭什么卡死？浏览器到底在挑哪一步的刺？我按现场顺序把这个坑拆开。

 

—先把现场摊开：能开网页 ≠ 能开摄像头—

打开手机浏览器。地址栏写的是示例地址 http://192.168.1.10:8080/。回车。标题出来了，按钮出来了，人觉得「通了」。

再点摄像头。这一步才翻车：有的机型直接提示无法使用相机，有的控制台里相关接口根本不存在。网络通、页面渲染通，只说明第三层还没验完。

示意：地址栏是 http://192.168.1.10 —— 页面能开，不等于摄像头能开

现场核对一句：先别改代码。先盯地址栏协议和主机名——很多时候锅不在业务逻辑，在浏览器安全门槛。

 

—对照地址栏：三种写法，三种命运—

把常见写法摊在桌上，一项一项点。这里说的是浏览器规则口径，不是某一家 App 私货。

  • http://localhost / http://127.0.0.1：在本机浏览器里，通常仍算安全上下文 Secure Context——调试摄像头时常能过。注意：手机浏览器敲 localhost，指的是手机自己，不是你的电脑。
  • http://192.168.1.10 这类局域网 IP：页面可以打开，但通常不算安全上下文。摄像头、麦克风一类敏感接口会被挡。
  • https://示例域名：走可信传输时，一般才进入「可以谈权限弹窗」的阶段。

示意对照：拒绝提示出现时，先回头看地址是不是纯 HTTP 局域网 IP

所以你会看见一种很气人的组合：电脑本机用 localhost 调试，摄像头好好的；换成手机访问同一台电脑的局域网 IP，页面还在，镜头没了。不是手机「挑剔」，是主机名换了，安全上下文规则跟着变。

【广告位1】

 

—钉死那个词：安全上下文—

浏览器把一批敏感能力关进「安全上下文」。摄像头相关的 getUserMedia（获取用户媒体）就在里面。官方材料写得很直：不在安全上下文时，相关对象常常是空的，调用直接失败。

翻车点就在这：HTTP 打开局域网页，对「显示 HTML」足够；对「打开镜头」不够。你以为是权限弹窗没出，其实更前面一道门就没进。

人话核对：安全上下文 ≈ 浏览器愿意相信「这条连接够稳、够干净，才让你碰相机」。局域网明文 HTTP 过不了这关；localhost 是例外通道，专给本机调试。

还有第二层：即便已经在安全上下文里，用户点了拒绝、系统相机权限关着、或页面嵌在别人的框里且策略不允许，照样开不了。那是权限层。朋友那晚的第一现场，多半先卡在上下文层。

 

—证书岔路：自签、装根、Let’s Encrypt—

想在局域网上也走 HTTPS，常见三条岔路。现场怎么选，看你能折腾到哪一步。

  1. 自签证书：服务端自己签一张。手机默认不信任，要装根证书或每次点「高级→继续」。能通，但同事一换手机又要教一遍。
  2. 本机/内网可信根：公司或自己维护一套根证书，设备预先信任。适合长期内网工具；家庭临时演示成本偏高。
  3. Let’s Encrypt 一类公开证书：好用，但签不了「只写纯私网 IP」那一张。它要验证你对某个公网可解析域名的控制权。没有域名、只有 192.168.x.x，这条路直接堵死。

很多人卡在幻想：「给我签一张 https://192.168.1.10 的正规证。」公开 CA 通常不干这事。要正规证，先准备域名，再用解析或 DNS 验证把它绑到你的服务上——服务本身仍可跑在局域网，但浏览器认的是域名那条 HTTPS。

示意：地址栏变成 https 且证书可信时，才轮到权限弹窗登场

 

—公网隧道：通是通了，账另算—

还有一派做法：用内网穿透/隧道，把本机服务映到带公网域名的 HTTPS 入口。手机打开的是隧道给的 https 链接——浏览器眼里已是安全上下文，摄像头路径往往就通了。

代价也要当场记账：流量出公网、依赖第三方、链接泄露等于把演示面敞开放。适合短时联调、远程演示；不适合把家里摄像头页面长期挂在随机公网域名上。别把相机权限永久开给来路不明的 HTTP 内网页。

示意对照：localhost / 局域网 IP / 自签 HTTPS / 公网隧道——通摄像头的条件不一样

【广告位2】

 

—普通人可抄结论—

别背一堆术语。把下面几条存进备忘，下次群里再吵「网页开了镜头不行」，直接甩。

  1. 手机打开局域网网页成功，只说明 Wi‑Fi 和端口通；不等于摄像头 API 可用。
  2. 先看地址栏：若是 http://192.168.…，优先怀疑安全上下文，而不是业务代码写错一行。
  3. 电脑本机调试优先 localhost / 127.0.0.1；手机要调电脑上的服务，准备 HTTPS + 可信证书，或短期公网隧道。
  4. 别指望公开 CA 直接签「纯私网 IP」证书；要证，先有域名验证。
  5. 权限弹窗出现仍失败时，再查系统相机开关、是否点过拒绝、是否嵌在别人页面里。

 

—你今晚就能做的—

  1. 打开出问题的那个页，截一张地址栏（示例 IP 即可），对照是不是纯 HTTP 局域网。
  2. 同一服务在电脑浏览器用 localhost 试摄像头：若本机行、手机局域网不行，基本坐实上下文问题。
  3. 若必须手机访问：列三条选项——自签并教手机信任 / 域名+正规证 / 短时隧道——挑你今晚耗得起的那条。
  4. 演示结束关掉隧道、收回权限；内网页不要长期挂「随便谁都能开镜头」。

适合谁：自己写了个本地页、想手机扫镜头做演示的人；带团队做内网工具、老被问「为啥手机不行」的人。不适合谁：指望我教你绕过浏览器安全去偷拍——那种需求，这篇直接停。

 

—结论—

这个坑不神秘：浏览器把「看网页」和「开摄像头」放在两道门槛后面。局域网 HTTP 常能过第一道，过不了第二道。看清安全上下文，你就知道该补证书、换域名，还是接受「今晚只用电脑本机调试」。

被这个坑卡住过的人，其实挺多——不是你笨，是规则本来就这么写。下次地址栏一亮 http://192.168，先笑一下：镜头的事，得另想办法。
