正文

桌面版 DeepSeek Harness 打开了，输入框也亮着——可你问一句，回答却像走错门：模型不是今晚想用的那条，供应商更是散落在各处，改一次配置就怀疑人生。

废话不多说。今晚只办一件事：把 DSH 接到本机 Magpie，并指定示例模型 laoli/gemini-3.8-flash-high。（示例供应商 id 用 laoli，你换成自己 Magpie「供应商」列表里的真实 id 就行。）先看接完之后路由长什么样——箭头对了，再回头补步骤也不迟。

 

—先看目标结果：路由该长这样—

接成功后，Magpie 的「模型 → 路由」里应能看到：左侧 DeepSeek Harness 挂着 laoli/gemini-3.8-…，右侧指向本机 127.0.0.1:3425。供应商状态里 Laoli 为启用。下面这张就是验收底牌——你照做完，对照它核一遍。

图：接完后的路由主卡。DSH → Magpie 网关 127.0.0.1:3425，模型前缀对得上 laoli。

真心建议一句：先记住这张图长什么样，后面每步都是在把它做出来。别急着开聊，箭头不对就别开始骂模型。

【广告位1】

 

—第一步，确认 Magpie 在跑—

要干嘛：确认 Magpie 认不认本机这些客户端，以及供应商列表里有没有你要用的那条。路径我写成 C:\Users\laoli——你本机换成自己的用户目录即可。

magpie ls
magpie providers

核对两件事。第一：列表里有没有 DeepSeek Harness。第二：供应商里有没有你的示例条目（文中写作 Laoli / id laoli）。本机网关记一下：http://127.0.0.1:3425/v1。网关没开，后面改配置等于空转——我自己一般是先看 Magpie 窗口还在不在，再敲命令。

图：magpie ls。红线那行是 DeepSeek Harness，后面跟的是它当前指向的模型。

 

—第二步，测通 laoli 供应商—

要干嘛：先证明供应商这条线本身活着，再改 DSH 默认模型。测不通就硬写配置，等于给自己挖坑。

magpie provider test laoli

我这边跑完是两条绿勾：chat 通路过、gemini 通路过。你照做时也盯这两行——都是 ✓，再往下写。若失败，先查供应商密钥与网络，别急着怪 DSH。

图：provider test laoli。chat 与 gemini 都打勾，才进入下一步。

 

—第三步，一条 magpie dsh 写入默认模型—

要干嘛：把 DeepSeek Harness 的默认模型指到 laoli/gemini-3.8-flash-high。Magpie 侧展示时可能带前缀，变成 magpie/laoli/gemini-3.8-flash-high——同一条模型，别被前缀吓到。

magpie models dsh
magpie dsh laoli/gemini-3.8-flash-high
magpie dsh

成功时会出现类似提示：✓ DeepSeek Harness model magpie/laoli/gemini-3.8-flash-high。再用 magpie dsh 回看一眼。这一步会写进桌面与 web 两套 profile 的 C:\Users\laoli\.dsh\profiles\*\cordis.patch.yml，并把 Magpie 写成 provider，baseURL 指向 http://127.0.0.1:3425/v1。

图：magpie dsh 查询与写入。绿勾那行就是默认模型已经落到 Magpie/Laoli。

 

—第四步，路由页与供应商页再核对—

要干嘛：命令行说改完了，打开 Magpie 窗口核一次箭头。点 模型 → 路由，对照开篇那张目标图；再切 模型 → 供应商，确认 Laoli 还在且启用。

图：红框对准 Laoli 供应商。其余条目已省略，避免干扰。

验收一句：路由能画到 「DeepSeek Harness → 127.0.0.1:3425」，且模型名前缀对得上 laoli。对不上，先别开聊，回头重跑 magpie dsh laoli/gemini-3.8-flash-high。

 

—第五步，DSH 新开会话验收；旧会话有坑—

要干嘛：回到 DeepSeek Harness，点 新会话 再聊。这不是仪式，是硬规矩：新会话才吃刚写进配置的默认模型；旧会话会继续握着自己当时的模型。还停在改配置前的那个对话里发消息，看起来就像「magpie dsh 白跑了」——我试过，骂了两分钟才想起来。

图：新会话主区。改完模型后来这里开聊；旧窗口要用 /model 或界面按钮再切一次。

旧会话想继续用？两条路：对话里敲 /model，或点输入框旁的模型按钮，手动切到 laoli/gemini-3.8-flash-high（或带 magpie/ 前缀的同名项）。我自己一般更省事——配置类改动，直接新开一扇。

今晚若只求「能在 DSH 里正常聊」，新会话发一句短问题即可。若 Magpie 提示 Web search 还没配搜索源——先忽略，不挡聊天主路径。

【广告位2】

 

—第六步，容易漏的三处 + 停止条件—

  1. Magpie 网关没开。桌面版 DSH 走本机 127.0.0.1:3425。Magpie 退出了，聊天直接断粮。改完也别随手关。
  2. 旧会话没切模型。默认模型只作用于之后新建的会话。旧的要 /model 或界面切换。
  3. 模型名 / 供应商 id 写飘。示例必须原样：laoli/gemini-3.8-flash-high；把 laoli 换成你自己的供应商 id 时，别少段、别多空格。

停止条件说清：供应商 test 不过，就不要硬改 DSH；路由页对不上箭头，就不要急着判断「模型不行」——多半是网关或旧会话问题。能做的是把线接上并指定模型；不能做的是指望旧会话自动跳过去。

 

—你今晚就能做的—

  1. 确认 Magpie 在跑，终端执行 magpie ls 与 magpie providers。
  2. 执行 magpie provider test laoli（换成你的供应商 id），两条通路都要 ✓。
  3. 执行 magpie dsh laoli/gemini-3.8-flash-high，再用 magpie dsh 回看。
  4. 打开 Magpie「路由」页，核对 DeepSeek Harness → 127.0.0.1:3425。
  5. 回到 DSH 新开会话再聊；旧会话记得手动切模型。

有底气，是因为验收点清楚：箭头在不在、新旧会话吃不吃配置、网关亮不亮。敢动手，是因为命令可复制、步骤不绕。今晚把线接上，明天再比模型谁更聪明——线都没通，比来比去都是空响。下期见。
