正文

群里有人甩了句：「我的 coding agent 每天半页「好的，我来帮你分析一下」，token 账单比代码还长。」下面立刻有人回：装 Caveman，少废话，能省大约六成。

仓库星标堆得吓人，文档也写得像石器笑话：why many token when few do trick。刷到的帖子口径几乎一边倒——说得更短、读得更少、自动挑模型还能更便宜。听起来挺有道理。问题是：真有那么玄吗？

 

—先顺着社区的吹法走半截—

Caveman 不是一个单独模型。公开材料里它至少两块石头：skill（少说）——逼 agent 答得短；本地 proxy（少读）——把日志、JSON、测试输出压短再喂给模型。新版本还叠了 Auto（自动挑模型/力度）、Blocks（脚本复用）等。

官方示例最常被转发的那句：同一道 React 重渲染解释，普通回复很长，Caveman 压成一两句，还甩出 useMemo。旁注常写「大约省六成」。Elastic、JetBrains、Adobe 的公开对照也被拿来当背书——听起来像：装上就能让账单瘦一圈，脑子还不掉。

只想「说得更短」、不想动代理？文档给了 skill-only 路径；想一把梭，主安装是一行 CLI（Node 要够新）。支持一长串 agent 名字——Claude Code、Codex、Gemini、OpenCode……社区帖子常把这些揉成一句：装了就省约 65%。

 

—怎么装、怎么开（你今晚就能做）—

我这边独立测试目录写成 /home/laoli/projects/laoli-demo-caveman-token-diet/。机器上 Node 已满足 ≥22.13。主路径我跑的是：

npx @caveman-ai/cli@latest
# 装完可用：cave --version
# 给 OpenCode 接线示例：
DO_NOT_TRACK=1 cave setup --yes --agents opencode

只要短回复、不接代理，用 skill-only：

npx skills add JuliusBrussee/caveman -g
# 装好后在 agent 里开：/caveman
# 更狠：/ultracave   文言风：/megacave
# 关掉：stop caveman  或  /caveman off

本机核到：CLI cave 4.0.1；skill 落在 ~/.agents/skills/caveman。文档站与仓库 INSTALL 还列了 30+ agent 的装法。不想上报使用统计：装的时候带 DO_NOT_TRACK=1，或事后 cave telemetry off。

本机：npx CLI 帮助、cave 版本、Node 版本、已装 caveman skill 列表

【广告位1】

 

—但公开材料里真正要紧的是：你自己比—

拧过来了。仓库自己的诚实页写得很直：相对一句「Answer concisely.」，/caveman 中位大概只再砍一丁点，/ultracave 才明显；历史里那套固定「省 65%」估算字段，现在不当真账。按「请求次数」计费的工具（比如某些 Copilot 额度），短回复也省不了次数。

所以社区那句「省约 65%」更像病毒口号 + 精选示例，不是你今晚随便一装就稳拿的账单折扣。官方也把 Read less（会话输入约少三成）、Auto（更便宜同水平）拆开写——别把不同石头的数字揉成同一个 65%。

我不用 Claude 账号也能比：同一模型、同一道题，一边普通系统提示，一边塞进 /caveman 口吻，用 tiktoken o200k 数输出。模型用 OpenCode 里的 DeepSeek 免费档。提示词原文如下——

【装前】Explain why this React component re-renders on every Parent render.
Give the cause and the recommended fix. Do not run tools.

function Parent() {
  return <Child style={{ color: "red" }} />;
}

【装后】在问题前加：
You are in /caveman mode. Follow caveman skill: answer first, kill ceremony,
short words, articles optional but never drop not/never/no/only,
one idea per sentence (≤20 words), code/paths/numbers verbatim,
no greeting/recap/closer.

第二道题是库存小函数：SKU 大小写对不上就漏检。同样装前装后各跑一遍，并要求写出回归风险——看短回复会不会把坑说丢。

The function below misses SKUs when casing differs (e.g. "ABC" vs "abc").
Propose a minimal fix, mention one regression risk, and show the changed function.
Do not run tools.

def find_sku(rows, sku):
    for row in rows:
        if row.get("sku") == sku:
            return row
    return None

质量并排看：两臂都点到「内联对象每次新引用」和「上提常量 / useMemo + memo」；SKU 题都提出 casefold，也都警告「大小写本就区分的 SKU 会被并错」。ultracave 更短，但对空值用了 str(...) 强转，比装前那种 isinstance / is not None 守卫略糙——短可以，别把防护句砍没。

所以你下次可以：别只信转发图里的百分比；用自己的日常题跑装前装后，把答文丢进 o200k（或直接看供应商用量页）。数字站哪边，你心里才有底气。

【广告位2】

 

—哪些站得住，何时别开—

站得住的：聊天解释、方案说明这类「废话多、代码块仍保留」的回合，少说这块确实能瘦输出；我这两题大约一半。官方 Read less / Auto / Blocks 是另一套机制，各有各的测法——可以分别开，别混进同一个「65%」里对外吹牛。

容易夸大的：把精选示例、论文/实验室对照、代理压缩、自动选模省钱，全糊成一句「装了省 65%」。skill 规则本身还要占一截输入；会话大部分是工具回传与代码时，只靠少说，账单可能几乎不动。

质量何时掉、何时别开：要逐步确认、安全警告、不可逆操作时，规则本来说要恢复完整句子——你若强行 ultracave，容易漏条件。已经写了「务必简洁」的团队规范时，再叠 Caveman，边际收益可能很薄。按次计费、不按 token 计费时，短回复省不了次数。自己 A/B 若账单更高：关掉就是，诚实页也这么劝。

 

—你今晚就能做的—

1. 确认 Node ≥22.13，跑 npx @caveman-ai/cli@latest 或 skill-only。
2. 挑一道你上周真实问过 agent 的题，装前装后各答一次。
3. 用 o200k 或账单页比输出（有代理再另记输入）。
4. 并排看：答案还能用吗？代码还准吗？否定句还在吗？
5. 省不够或质量掉 → /caveman off，别为了梗硬扛。

刷帖可以被忽悠一次；自己比完，就不会第二次。少废话值得装着玩，但别把口号当成你的账单。
