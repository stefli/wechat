正文

朋友把 coding agent 的月账单截图丢进群里：大半页都是「好的，我来帮你看一下」「总结一下上面几点」。有人立刻回：装 Caveman，少废话，能省大约六成。

这是眼下很常见的误判——把仓库口号、精选示例、代理压缩、自动选模，揉成同一个百分比。真的是那样吗？分两层看更清楚：它到底改了什么，以及你自己的任务能省多少。

 

—先分清它改的是哪一层—

Caveman 不是换一个更便宜的大模型。公开材料里至少两块：skill（少说）压短回复；本地 proxy（少读）把日志、JSON、测试输出压短再喂给模型。另外还有 Auto（按题选模型/力度）、Blocks（脚本复用）等。因为机制不同，所以数字不能直接相加。

官方写的是：Say less 有精选示例；Read less 整段会话输入大约少三成；Auto 相对高配基线更便宜。我读下来是：每一块要单独核。仓库诚实页还写明——相对已经写了「Answer concisely.」的基线，/caveman 中位再砍得很薄，/ultracave 才明显；历史那套固定「省 65%」估算字段，现在不当真账。

能做：给 agent 加短答规则，或接本地压缩代理。不能做：指望一行安装就等于账单永久打六五折——尤其在按「请求次数」计费、而不是按 token 计费时，短回复省不了次数。

 

—安装分两条路径，别混—

测试目录写成 /home/laoli/projects/laoli-demo-caveman-token-diet/。前提是 Node ≥22.13。主安装一行：

npx @caveman-ai/cli@latest
# 装完自查：cave --version
# 给 OpenCode 接线示例：
DO_NOT_TRACK=1 cave setup --yes --agents opencode

只要短回复、不接代理，用 skill-only。官方写的是全局加 skill，装好后在对话里开 /caveman：

npx skills add JuliusBrussee/caveman -g
# 开：/caveman    更短：/ultracave    文言风：/megacave
# 关：stop caveman   或   /caveman off

本机核到：CLI 当前版；skill 落在 ~/.agents/skills/caveman。INSTALL 文档列了 30+ agent。不想上报使用统计：安装时带 DO_NOT_TRACK=1，或事后 cave telemetry off。

本机：CLI 帮助、cave --version（版号已遮）、Node≥22.13、已装 caveman skill 列表

【广告位1】

 

—同一题对照：比口号更要紧—

证据到哪为止：本篇只测 skill 口吻对输出长度的影响——同一模型、同一道题，装前普通提示 vs 装后 /caveman 规则；用 tiktoken o200k 数答文。模型走当前 OpenCode 里的 DeepSeek 免费档。不依赖 Claude 账号。没有把 proxy 整段会话账单写成「省 65%」。

第一道题是社区常用的 React 内联 style 重渲染。提示词原文：

【装前】Explain why this React component re-renders on every Parent render.
Give the cause and the recommended fix. Do not run tools.

function Parent() {
  return <Child style={{ color: "red" }} />;
}

【装后】在问题前加：
You are in /caveman mode. Follow caveman skill: answer first, kill ceremony,
short words, articles optional but never drop not/never/no/only,
one idea per sentence (≤20 words), code/paths/numbers verbatim,
no greeting/recap/closer.

第二道题看质量会不会掉：库存 find_sku 大小写漏检，要求修法 + 一条回归风险 + 代码。因为短答最容易砍掉的是否定句和边界提醒。

The function below misses SKUs when casing differs (e.g. "ABC" vs "abc").
Propose a minimal fix, mention one regression risk, and show the changed function.
Do not run tools.

def find_sku(rows, sku):
    for row in rows:
        if row.get("sku") == sku:
            return row
    return None

 

—输出大约省一半，不是整齐的六五折—

本篇测到的输出 token（o200k，仅答文）：

React 解释：装前 285 → /caveman 151（省 47.0%）
SKU 修复：装前 233 → /caveman 111（省 52.4%） → /ultracave 100（省 57.1%）
两题 /caveman 均值约 49.7%。因为任务偏「解释 + 方案」，废话空间大，所以省得到；这不等于所有会话类型都稳在这个区间。

同一模型·同一题·o200k：两题约省一半；口号约65%未落在本表均值

上：装前；下：/caveman。因果与修法都在，篇幅明显短

质量边界：两臂都点到「内联对象每次新引用」和「上提常量 / useMemo + memo」；SKU 题都提出 casefold，也都警告大小写本就区分的 SKU 会被并错。ultracave 更短，但对空值用了 str(...) 强转，比装前 isinstance / is not None 守卫略糙。短可以，别把防护句砍没。

所以你下次可以：用自己上周真实问过的题，装前装后各跑一次，答文丢进 o200k 或直接看供应商用量页。数字站哪边，再决定开不开——这比转发图里的百分比更有底气。

【广告位2】

 

—适合开 / 适合关，按场景选—

更适合开的：聊天解释、方案说明——废话多、代码块仍要保留的回合；本篇两题输出大约砍一半。若还要动 Read less / Auto / Blocks，当作另一层开关单独核，别并进同一个「65%」对外说。

容易夸大的：精选示例、实验室对照、代理压缩、自动选模省钱，糊成一句「装了省 65%」。skill 规则本身要占一截输入；会话主体是工具回传与大段代码时，只靠少说，账单可能几乎不动。

建议先关或慎开的：逐步确认、安全警告、不可逆操作——规则本身要求恢复完整句子，强行 ultracave 容易漏条件；团队规范已经极简时，边际收益薄；按次计费工具上，短回复不省次数；自己 A/B 若账单更高，关掉即可，诚实页也这么写。

 

—今晚可执行的五步—

1. 确认 Node ≥22.13，跑 npx @caveman-ai/cli@latest 或 skill-only。
2. 挑一道真实任务，装前装后各答一次。
3. 用 o200k 或账单页比输出；开了代理再另记输入。
4. 并排核：答案可用吗？代码准吗？否定句还在吗？
5. 省不够或质量掉 → /caveman off，按场景取舍，不为口号硬扛。

分清层次、自己对照过，才知道该信哪一格数字。少废话值得试；别把口号当成你的账单。
