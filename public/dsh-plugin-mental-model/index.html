【公众号账号】

命令行里提示装成功了，打开 DeepSeek Harness 桌面版却看不见插件——听起来像软件坏了。更常见的误判是：以为「装了就到处都有」。

只要认清 profile：插件装进某一套 profile，不是装进「整个 DeepSeek」。认清层，桌面版才能看见你装的插件。今晚任务：把 profile / plugin / Web（桌面壳） 三层钉死，再决定动手动哪一层。

真的是装了就到处都有吗？分两层看——先看现象，再看它装进了哪套柜子。

 

—两个常见卡点—

卡点一：装错 profile。对 web 执行 add 成功，desktop 侧栏完全没有——不是失败，是装进了另一套柜子。桌面版独占 desktop 这套；终端默认常走 web。

卡点二：层没分清就动手。把「插件市场页签」「第三方 npm 插件」「内置可配置项」当成同一抽屉；或桌面版还在跑时硬改 desktop 包，撞写锁、装一半。

要紧的是：先问自己要改哪套 profile。说不清，就先别 add。

【广告位1】

 

—一个方案：三层心智，先认层再装—

因为 DSH 把能力拆成三层看更清楚。profile 是一套有序的插件补丁栈，落在用户目录下的 .dsh/profiles/<名字>；plugin 是装进某套 profile 的能力包；Web / 桌面壳 只是把同一类 Web 应用包进窗口——插件图仍按 profile 解析。

官方边界读下来是：Electron 拥有 desktop profile；普通 CLI 不能启动它。所以「命令行装成功」只证明那条命令写进了你指定（或默认）的 profile，不证明桌面柜里也有。

desktop profile 的 dependencies 与 bundles——第三方插件会出现在这里。

 

—插件和市场不是同一抽屉—

能做 / 不能做先划清：插件是能力包；「插件市场」页签通常来自你装上的市场类插件（例如 dshmarket），它是逛商店的界面，不是宿主自带的全部库存。内置插件配置则是宿主自带的可调项——子智能体、网页搜索、Agent 循环、终端——和第三方 npm 插件不是同一抽屉。

红框：已安装 / 插件市场——先认页签，再谈乱装。

子智能体、网页搜索、Agent 循环、终端——内置可配置项，与第三方插件分抽屉。

 

—乱装会出什么问题—

  • 对 --profile web 装成功，桌面版完全看不见——最常见误会。
  • 桌面版还在跑时硬改 desktop 包，撞写锁或装一半。
  • 第三方插件与宿主同机同权：能碰工作区文件——不是浏览器扩展那种沙箱。
  • 公司 npm 源拉包失败时，可改回官方源再试；源不通不要硬判「插件坏了」。

 

—分步：今晚怎么检查、怎么装对—

方案落地就四步。先看你要改的是桌面还是 Web；改桌面就退出应用，再用桌面自带命令，并显式带上 --profile desktop。

  1. 打开桌面版 → 插件页，看「已安装 / 插件市场」是否符合预期。
  2. 若要用命令行改桌面插件：托盘里退出 DeepSeek Harness。
  3. 调用桌面安装目录里的 resources\runtime\cli\bin\dsh.cmd，对 --profile desktop 执行 list/add/remove。
  4. 再打开桌面版验收；不要假设 PATH 上一定有全局 dsh。
dsh plugin --profile desktop list
dsh plugin --profile desktop add <包名>

验收一句：desktop profile 上 list 的结果，要和 package.json 里的 dependencies / bundles 对得上。对不上，先别急着 add。

desktop profile 上执行 dsh plugin list——依赖条目与 package.json 对得上。

【广告位2】

 

—容易漏的边界—

证据到本机 profile 目录与官方桌面文档为止。不同机器若 PATH 已注册「管理 dsh 命令」，终端里直接敲 dsh 也可以，但改桌面仍要指定 desktop。

今天只钉「装在哪一层」：能认页签、能打开 desktop 的 package.json、能对指定 profile 跑 list。不保证某个第三方插件今晚一定好用，也不把 Web 壳和桌面壳说成同一份库存。

不要把 web 与 desktop 当成同一个商店库存。只玩浏览器版就固定 --profile web，别和桌面混着装。

 

—最后—

写到这里，把意图再说清楚：DeepSeek Harness「一切皆插件」之前，先认层。只要认清 profile，你才知道桌面版为什么看不见命令行刚装的包——多半不是坏了，是柜子不对。

边界就一句：今晚验收是「层分得清、list 对得上」；不替某个第三方插件背书，也不鼓励桌面还在跑时硬改包。分得清层，你才有底气说「我不是装失败，是装错柜子」。
