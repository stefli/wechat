正文

群里常有人说：「我命令行装上了，桌面版怎么没有？」听起来像软件坏了，其实多半是装错层。

今晚任务：把 DSH 的三层心智钉死——profile、plugin、Web/桌面壳——再决定你该动哪一层。

真的是「装了就到处都有」吗？分两层看。

- - -

DSH 的插件，到底装在哪？

短答：装进某一个 profile，不是装进「整个 DeepSeek」。

因为 profile 是一套有序的插件补丁栈，落在 $DSH_HOME/profiles/<名字>。桌面版独占 desktop 这套；你在终端对 web 执行的 add，默认进的是另一套柜子。

desktop profile 的 dependencies 与 bundles——第三方插件会出现在这里。

官方写得很清楚：Electron 拥有 desktop profile；普通 CLI 不能启动它。桌面壳只是把 Web 应用包进窗口，插件图仍按 profile 解析。

【广告位1】

插件和市场又是什么关系？

短答：插件是能力包；市场是逛商店的界面插件。

侧栏点「插件」，会看到「已安装」和「插件市场」页签。市场页签通常来自你装上的市场类插件（例如 dshmarket）；内置插件配置则是宿主自带的可调项。

红框：已安装 / 插件市场——先认页签，再谈乱装。

子智能体、网页搜索、Agent 循环、终端——这些是内置可配置项，和第三方 npm 插件不是同一抽屉。

乱装会出什么问题？

短答：装错 profile、装重、或把实验插件塞进日常桌面。

  • 对 --profile web 装成功，桌面版完全看不见——最常见误会。
  • 桌面版还在跑时硬改 desktop 包，撞写锁或装一半。
  • 第三方插件与宿主同机同权：能碰工作区文件——不是浏览器扩展那种沙箱。

今晚怎么检查、怎么装对？

短答：先看你要改的是桌面还是 Web；改桌面就退出应用，再用桌面自带命令。

  1. 打开桌面版 → 插件页，看「已安装 / 插件市场」是否符合预期。
  2. 若要用命令行改桌面插件：托盘里退出 DeepSeek Harness。
  3. 调用桌面安装目录里的 resources\runtime\cli\bin\dsh.cmd，对 --profile desktop 执行 list/add/remove。
  4. 再打开桌面版验收；不要假设 PATH 上一定有全局 dsh。
dsh plugin --profile desktop list
dsh plugin --profile desktop add <包名>

所以你可以：把「我要改哪套 profile」写成今晚的检查句；说不清就先别 add。

【广告位2】

边界到哪为止

证据到本机 profile 目录与官方桌面文档为止。不同机器若 PATH 已注册「管理 dsh 命令」，体验里直接敲 dsh 也可以，但改桌面仍要指定 desktop。

今天只钉「装在哪一层」：能认页签、能打开 desktop 的 package.json、能对指定 profile 跑 list。不保证某个第三方插件今晚一定好用，也不把 Web 壳和桌面壳说成同一份库存。

不要把 web 与 desktop 当成同一个商店库存。

你今晚就能做的

  1. 打开插件页，确认「已安装 / 插件市场」页签含义。
  2. 打开 desktop 的 package.json（只读），看 dependencies / bundles 里有没有你以为装上的包。
  3. 退出桌面应用后，对本机 desktop profile 跑一遍 dsh plugin --profile desktop list，对照终端输出。
  4. 若要对桌面动手：先退出应用，再对 desktop profile 操作 add。
  5. 只玩浏览器版就固定 --profile web，别和桌面混着装。

desktop profile 上执行 dsh plugin list——三条依赖与 package.json 对得上。

list 对得上，你才有底气说桌面柜里现在有什么；对不上，先别急着 add。

分得清层，你才有底气说「我不是装失败，是装错柜子」。下一篇我们只装 2～3 个可验收的首批插件。
