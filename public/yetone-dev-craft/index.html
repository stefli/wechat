朋友说得对，yetone 更值得学的不是工具，是他那几招

近期写完 Magpie 那篇，朋友私信一句：「工具可以装，但 yetone 更值得学的是开发技巧。」当晚我把聊天窗一丢，去翻他的公开仓库和推文。

我自己是供应链里做架构的，平时爱拿 Agent（智能体）写代码、跑流水线。朋友这句话戳中我了：装网关、换模型，谁都会；真正难的是，让一堆 Agent 天天改仓库，还不把项目改散。下面按公开材料，把我抄下来的几招讲清楚——Magpie 只当他作品里的一个例子，不当功能二刷。

· · ·
他是谁，一笔带过就行

GitHub 上的 yetone，写作这天大约 9400+ 粉丝、六百多个公开仓。自述爱做开发者工具，迷恋终端和键盘肌肉记忆。你可能听过 Neovim 里那套 AI 写码插件 avante，或者 Bob 划词翻译那一脉插件生态；近一点的还有 Magpie 本地模型网关、Cumora 这类 Agent 协作玩具，以及把「原生感」「杀 AI 味」打成 Skill 的仓库（native-feel-skill、kill-ai-slop）。

产品很多，本稿不排年表。我想盯的是同一件事：他怎么让 Agent 写代码、改代码、合代码，还能把翻车收成规矩。

· · ·
三个 Agent 一起跑，人只管晚上收货

他在推上说得很直：没有魔法，甚至觉得分享出来毫无意义——就是用 Claude Code，配官方 Opus 5.5 跑 loop；并行跑图里的 3 个 loop，然后每晚抽时间铲屎，主要盯 UI/UX。那条工作流帖，曝光大约 38.6 万、点赞两千八百多。

这很像供应链里开多条拣货通道：货可以并行冲，人不去逐箱装箱，而是盯出口质检和异常回退。Agent 负责吞吐，人负责「今晚这一批能不能过闸」。我没在本机开三条平行会话照抄他的算力布局；可抄的是分工——让 Agent 冲，人守边界和收货。

· · ·
每晚复盘进 LESSONS，见三次就升成标准

Magpie 仓库里有一份 LESSONS.md。开篇就写：代码由 Agent 编写、评审、合并、发布；每晚复盘「又修了什么、不该合什么、验证太薄的是什么」；每条课见写成规则 + 原因 + 证据；见过 ≥3 个不同日子，就升进 docs/code-standards.md。

仓库公开摘录：LESSONS 写明 Agent 写审发，课见三次进标准

节奏数字也写在文件里：2026-10-05 一天约 220 次提交、~170 次发布；其中大约四十次在修当天或前一天刚放出的问题。10-08 又是 192 次提交、18 次发布。不是玄学，是「翻车进台账，台账够次数就变硬规矩」。

仓库公开摘录：修一类、失败读=unknown、不覆盖用户自设等硬规则

供应链里也一样：同一类过闸事故见三回，就不能再停在口头提醒，得写进作业标准。Agent 时代更需要这份耐心——它写得快，你若不记账，同一坑会按小时复读。

· · ·
同一类 bug，一次修干净

LESSONS 里反复出现的一句：修一类，不修截图里那一例。报告里某个 Agent 坏了，就去搜同形态的兄弟路径——别的 Agent、别的子命令、同一谓词的调用点——同一次改完。文件里写过：有问题修了四轮，每一轮只修截图里那个 Agent。

还有几条我直接抄进备忘：读失败、解析失败，结果是 unknown，绝不当成空、无、相等；访问控制类列表读不到文件时要失败关闭，不能当成空名单放行；不要用默认值盖掉用户自己设过的项；测试不碰真机上的 Agent 配置；大提交的说明里写清楚跑过什么。

这些听着像常识，可 Agent 最容易犯的就是「只修眼前那一例」。人做质检时，我也见过：挑出一箱错贴，只换那一箱标签——下周同款错贴又来。修 sibling，才是把质检做成工艺。

· · ·
边界外挂：插件化，连品味也打成 Skill

他在推上补充过设计意图：核心想做的是一个本地 router，routing 是目标；为了避险，已经把供应商彻底解耦、做成插件。谁进核心、谁外挂，这是边界感——Bob 年代就在玩插件边界，到 Magpie 还是同一肌肉。

作品举例：本地网关 Running——本稿只当手艺长出来的产品之一

更可抄的是另外两个仓库：native-feel-skill 把跨平台桌面「原生感」拆成 Agent 可读的宗旨、架构、清单；kill-ai-slop 把「AI 产品味」反模式写成可扫描、可修复的 Skill。品味不再停在作者脑子里，而变成项目里能加载的文件。

公开结构：SKILL + references + 75 项上线清单

公开摘录：把「杀 AI 味」固化成扫描→分诊→修复的流程

近期我在 Linux 上摸过 Magpie：装得上、网关起得来，也接通过真实 Gemini 做连通试。那是产品层的体验。这篇想带走的，是它背后那套「边界外挂 + 规矩可执行」的工程味道。

· · ·
能抄规则，别幻想抄算力

他真在多机会话和订阅沙盒里日夜滚；我们读到的是公开纪律和推文自述。单日两百多次提交、近两百次发布，背后是机器吞吐和人每晚铲屎，不是一句「用了 Agent」就能复制。

我能马上落地的，是半页备忘：① 并行开任务时，人只守出口质检；② 翻车写进 LESSONS 式台账，见三次升标准；③ 修一类不修一例；④ 默认配置永不踩用户自设；⑤ 把反复强调的品味，收成 Agent Skill 文件。工具明年还会换；这五条不换。

· · ·
工具会换，规矩更耐用

朋友说得对。yetone 更值得学的不是再装一个星标工具，而是他把 Agent 当产线工人用时，仍坚持记账、升标准、修一类、守边界。Magpie 只是这套纪律长出来的产品之一。

你要是也在用 Agent 改仓库，不妨今晚先开一个空文件，把今天翻过的坑写进去。写三条就够。见第三次，再决定要不要升成团队标准。

觉得有用的话，点个关注「老李的AI江湖」，顺手转发或点个赞，下期见。
