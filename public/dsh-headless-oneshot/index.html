正文

旧做法：打开桌面版，点新会话，粘提示词，等气泡，再复制结果。

新做法：终端里丢一行，答完就退出，stdout 拿走结果。

今晚把这两个入口的边界问清楚——尤其是「我电脑上没有全局 dsh」怎么办。

- - -

headless 是什么？

短答：无界面、一次任务、答完退出的 profile。

官方帮助写的是：答案走 stdout，诊断走 stderr；可从参数或管道读入任务。它适合脚本、CI、批量，不适合你要盯着插件市场点点点的晚上。

本机实测：version 与 headless --help；选项以你机器帮助为准。

把它想成「一次性工单」：进来、干活、把结果吐到标准输出、走人。对话历史不是它的主场，脚本编排才是。今晚先跑通一行，再谈管道和定时。

【广告位1】

什么时候 Web/桌面不够用？

短答：你要的是「跑完返回」，不是「坐在窗口里聊」。

  • 定时脚本要调用一次 Agent 并解析输出。
  • SSH/无桌面不方便操作 GUI。
  • 同一条任务要重复跑，点 UI 会疯。

桌面适合点选插件与看会话；headless 适合一条命令交付。

我电脑没有全局 dsh，还能跑吗？

短答：能。用桌面版自带的 dsh.cmd。

本机实测：PATH 里未必有 npm 全局 dsh；但安装目录 resources\runtime\cli\bin\dsh.cmd 可用。也可在桌面菜单用「管理 dsh 命令」注册到用户 PATH——注册后新开终端再试 dsh --version。

cd C:\Users\laoli\Documents\dsh-demo-headless-oneshot
& "C:\Users\laoli\AppData\Local\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd" --version
dsh --profile headless "用一句话介绍 DeepSeek Harness"

一条命令长什么样？验收怎么做？

短答：进示例目录，headless 提问，看 stdout 是否给出完整句并退出。

本机验收：stdout 给出一句中文介绍，进程退出。

所以你可以：把这行放进脚本；需要机器可读事件时再加 --json（以本机 --help 为准）。

【广告位2】

桌面入口和 CLI 的边界？

短答：CLI 唤不醒桌面窗口；desktop 插件要退出桌面后再改。

  • 要 GUI：点桌面版图标。
  • 要 oneshot：headless profile。
  • 本机帮助里若没有某旗标（例如较新的 approval 相关选项），不要照抄网上未验证参数。

不要编造「本机已用某旗标跑通」——以 dsh --profile headless --help 为准。

你今晚就能做的

  1. 找到桌面自带 dsh.cmd，跑 --version。
  2. 建示例目录，跑一条 headless 问题。
  3. 确认 stdout 有答案、进程退出。
  4. 若只要点选插件，继续用桌面版即可，不必强行 headless。

问清楚入口，你才不会在「没有全局命令」时误以为 DSH 不能脚本化。
