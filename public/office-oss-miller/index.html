【公众号账号】

对账表分散在几份 CSV 里。你打开一份，往下复制，再打开另一份。还没开始汇总，就得先盯着表头，担心多贴了一行，或者把重复发来的记录又算进去。

麻烦还不只在合并。客户编号有开头的零，备注里也可能带逗号。表看着差不多，一次复制或一次自动转格式，就可能让后面算出来的数失去依据。

这次我用 Miller 做一条短流程：把同表头的示例 CSV 合起来，去掉完全相同的整行，再按客户算总额。先不碰复杂的业务匹配。能不能把这件日常小事做得清楚，又让每一步都有表可查？

—先把材料放在一起，别急着算—

在“我的文档”里新建CSV对账文件夹。先按下面全文保存周一.csv、周二.csv；后面做格式检查时，再保存另外两份边界 CSV。内容都是独立制作的练习材料，不是客户表，也不依赖上一篇文章。

下文用/home/laoli/Documents/CSV对账/。照做时换成自己电脑上的实际位置。保留输入文件，生成文件另起名字；已有重要的同名结果就先移到别处，别让重定向写出把它覆盖。

用下面内容制作两份 CSV。用纯文本编辑器分别保存为UTF-8 编码的周一.csv、周二.csv，不要把后缀存成 .csv.txt。先核表头：客户编号、订单号、物料、金额分、备注，顺序一致。字段名保留下面的英文，命令会按名字找列。

周一.csv：

customer_id,order_id,item,amount_cents,note
0007,PO-001,轴承,125000,"含税,含运费"
0012,PO-002,密封圈,8850,"规格 ""A"""
0007,PO-003,胶带,1990,常规

周一.csv 的真实打开画面：备注里的逗号包在引号内，双引号按 CSV 格式转义。

周二.csv：

customer_id,order_id,item,amount_cents,note
0012,PO-002,密封圈,8850,"规格 ""A"""
0012,PO-004,纸箱,12400,二批
0100,PO-005,标签,760,加急

周二.csv 第一条与周一的 PO-002 完全相同。不要只凭订单号决定删哪行。

customer_id 是编号，amount_cents 才是要计算的金额。这里金额单位为分，不是元。含税与否也不是软件猜的，备注只是文本。先把这层意思看明白，再运行汇总，后面的数字才有口径。

—装好 Miller，认准 mlr 这个命令—

Miller 是按字段名处理表格文本的开源命令行工具。官方支持 CSV、JSON 等格式，使用BSD-2-Clause许可证；再分发需保留相应版权、条款及免责声明。官方近期仍有发布。下面只做合表、去整行重复和汇总，不展开其他功能。

这次实际在Linux运行。Debian／Ubuntu 需联网、有可用软件源和sudo 管理员权限。打开终端，逐行执行。任一步失败先停，不要带着安装错误继续处理材料。

sudo apt-get update && sudo apt-get install -y miller
command -v mlr
mlr --version
mlr --help
cd "/home/laoli/Documents/CSV对账"

能看到命令路径、版本信息和帮助，再往下走。安装包叫 miller，命令叫 mlr。它不是 Python 工具，不用安装 pip、建 venv，也不用另改 PATH。若 command -v 找不到它，就先确认安装是否成功，不要把后面的命令名改成 miller 试运气。

【广告位1】

—第1步：先查格式，再合成一张表—

打开两份原文，确认都有同样的五个表头，特别是amount_cents。确认单位和编码一致，再做格式检查。下面一组命令逐行执行，echo 紧跟上一行；不是 exit:0，就先停。

mlr --csv check 周一.csv 周二.csv
echo exit:$?

这次检查通过。check 只告诉我们这些 CSV 能不能按格式解析，不是必需列验证，更不会判断客户和金额是否合理。这个差别后面用边界文件看。现在把两份表纵向接起来。

mlr --csv -S cat 周一.csv 周二.csv > 合并原表.csv
echo exit:$?

合并原表.csv 有 6 条数据，不含表头。两份各 3 条都进来了，重复的 PO-002 也还在，文件为 266 字节。-S 的意思是关闭自动类型推断，先把字段当文本处理。编号不参与加减，就先保留它原来的写法。

—第2步：只去掉完全相同的整行—

重复发来的那条，可以去掉。但如果同一订单的金额或备注改了，是否覆盖旧记录，就不是这条命令能决定的事。这里用uniq -a，比较的是完整记录。

mlr --csv -S uniq -a 合并原表.csv > 明细去重.csv
echo exit:$?

这次留下5 条明细，明细去重.csv 为 224 字节。少掉的是那条完全相同的 PO-002。这不是按订单号识别业务重复。同订单不同金额、不同备注，仍是不同整行，得另外确认业务含义，不能直接删。

终端依次执行 check、cat 和 uniq -a；各次 exit:0，合并文件 266 字节，去重明细 224 字节。

用LibreOffice Calc打开明细去重.csv。导入窗口选择UTF-8，先看预览是否按逗号分列。这次是自动检测；没分开再手动选逗号。点第一列，把列类型设成Text（文本），再确认导入。

UTF-8 与第一列 Text。编号按文本读入，避免在查看结果时另被表格软件转成数字。

五条明细实际打开后的样子。客户编号、备注逗号和嵌入引号都保留。

我会在这一步停一下。看 PO-002 是否只留一条，也看0007、0012、0100有没有变样。合并和去重只处理记录，不能代替这次目视核对。你换自己的材料，也先看明细，再让它往下算。

—第3步：只把金额转整数，再按客户汇总—

现在才动金额列。下面把amount_cents 转为整数，按 customer_id 分组，求和并计数，最后按客户编号排序。then 把这些处理接在一起。客户编号不做数值转换。

mlr --csv -S put '$amount_cents=int($amount_cents)' then stats1 -a sum,count -f amount_cents -g customer_id then sort -f customer_id 明细去重.csv > 客户汇总.csv
echo exit:$?

生成客户汇总.csv后，用纯文本编辑器或 Calc 打开。用 Calc 时仍把第一列按 Text 导入。下面是实际终端内容和表格，金额单位仍是分，尚未自动换成元。

终端实际执行整数转换、分组汇总和排序，返回 exit:0，再列出客户汇总.csv。

终端列出三个客户的金额分和记录数；客户汇总.csv 为 86 字节。

三个客户完整显示。amount_cents_sum 是金额分合计，amount_cents_count 是参与汇总的记录数。

  • 0007：126990 分，2 条。125000+1990=126990。
  • 0012：21250 分，2 条。8850+12400=21250。
  • 0100：760 分，1 条。总计 149000 分，即1490.00 元，计数合起来为 5。

本次按整数分计算，也用独立的整数求和核过结果。它没有替我们识别币种、税率或退款方向。你自己的表如果存的是元，或者混了不同币种，就不能照抄这个字段名和单位直接算。

—验收时，再分清格式和你需要的列—

在同一文件夹里，再用纯文本编辑器把下面全文保存为 UTF-8 编码的缺列示例.csv。表头是 5 列，下面故意只写 4 个字段。不要补逗号；这里观察格式错误，不把它接进主流程。

customer_id,order_id,item,amount_cents,note
0007,PO-BAD,轴承,125000

文件保存好后，运行：

mlr --csv check 缺列示例.csv
echo exit:$?

表头 5 列、记录 4 字段；实际 check 报 header/data length mismatch 5 != 4，返回 exit:1。

错误近景：header/data length mismatch 5 != 4，本行字段数与表头不一致。

再把下面全文以 UTF-8 保存为缺金额列.csv。这回整列 amount_cents 都没有了，表头和数据却各有 4 个字段，格式是完整的。

customer_id,order_id,item,note
0007,PO-NOAMOUNT,轴承,缺金额列

mlr --csv check 缺金额列.csv
echo exit:$?

没有 amount_cents 的实际表头和记录；同一文件 check 返回 exit:0。

所以 check 不是必需列校验。格式通过后，仍要对照开头的五个表头，确认列名、单位和记录内容。这份结果只有在你确实需要的列都存在时，才值得继续处理。

要交给读取 JSON（带类型的文本数据格式）的后续程序，可以加做下面这个小检查。它不改变合表任务，只把去重明细转换格式，方便看清类型。

mlr --icsv --ojson -S put '$amount_cents=int($amount_cents)' 明细去重.csv > 明细.json
mlr --ijson --ojson head -n 1 明细.json

第一条中 customer_id 是带引号的字符串 0007，amount_cents 是不带引号的整数 125000。

本次还逐条核过完整 JSON：编号、中文和备注内容都在，金额分为整数。不要反过来把 customer_id 也转整数；那会改变编号的写法。这里显式用 -S 保持处理口径，并不是说 Miller 默认一定会丢前导零。

【广告位2】

—我的经验教训：每做完一步，都留下能查的表—

我更愿意保留合并原表、去重明细和客户汇总，而不是一次覆盖掉输入。结果不对时，可以往回找：是原文件就少了一条，还是去重口径不对，或者金额列本来不是分。多留这几份小文件，比只拿到最后一个总数更容易查清来处。

这次也提醒我，CSV 的双引号不是类型声明。它负责把逗号、双引号等内容安全包进字段。备注里的逗号不是新的一列，不能直接按每个逗号拆文本。编号要当文本的意图，也该在处理命令和 Calc 导入里分别说清楚。别以为其中一处保住了，另一处就不会再变。

还要留意源文件的编码。本次两份输入都是 UTF-8，中文和引号已核对；没有验证自动识别其他编码、混合币种或订单修订。如果打开就乱码，先把输入编码弄清楚，不要继续合表。金额超过工具整数范围、含小数或有异常空值，也需要另做校验，不能把本次较小整数分的结果当成任意财务计算保证。

—最后—

先用这两份示例走完一遍，再换自己的表。表头和单位看明白，明细查过，再看汇总；业务上要不要删一条记录，仍由人确认。命令行不必一开始学很多，先把这条小流程做稳，就有了一种处理多份同结构表格的办法。
