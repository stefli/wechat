正文

短片草稿堆在桌面，旁白还空着。群里有人甩一句：微软 Ana 童声很好听，科技博客那种沉稳男声也好认——但云端按字计费，草稿改三遍钱包先响。

有人回：开源 Kokoro，八千多万参数，本机就能跑。我是老李。当场新建空目录，打开终端，想看一件事：它会不会在安装这一步就翻车？翻车了还能不能出两路能听的旁白？

 

—先摊开目录，别碰别的工程—

独立测试目录我写成：/home/laoli/projects/laoli-demo-kokoro-82m-local-tts/。只开这一夹，不把正在写的工作区拖进来。目标很具体：一路儿童感样音，一路科技博客男声样音，都落成 24kHz 的 WAV。

先说清对照口径，免得被标题带跑：Azure 的 en-US-AnaNeural 是英童声；Kokoro 没有同名 Ana。我们做的是「童声感」与「科技男声」两路逼近，不是一键克隆微软音色。

 

—第一步：把依赖粘上—

机器是 Linux，没有独显，就走 CPU。系统自带 Python 偏新时，Kokoro 当前版会直接装不上——我这边用 uv 拉了 Python 3.12 虚拟环境才过。完整命令如下，你可以直接复制：

sudo apt-get update && sudo apt-get install -y espeak-ng libsndfile1

uv venv --python 3.12 .venv
source .venv/bin/activate

# 装 CPU 版 torch（按 PyTorch 官网当前 CPU 指引选轮子）
uv pip install torch
uv pip install 'kokoro>=0.9.4' soundfile 'misaki[zh]'

核对项就三件：espeak-ng --version 有输出；python -c "from kokoro import KPipeline; print('ok')" 打印 ok；中文还要 misaki[zh]，英文会顺带拉 spaCy 小模型。

核：venv 起得来、torch 与 kokoro 能 import

翻车点就卡在 Python 版本。系统若是 3.13，硬装 kokoro>=0.9.4 会提示无匹配发行版。不要硬改源码绕版本；先换 3.12 虚拟环境再装。我没换到 Windows 机，Linux CPU 这条线装通了。

【广告位1】

 

—第二步：中文管道先出声—

打开 Python，先起中文管道。关键参数是 lang_code='z'，音色名要和语言对上。

from kokoro import KPipeline
import soundfile as sf

pipe_z = KPipeline(lang_code='z')  # 中文
text = '''从前有一只小狐狸，住在山脚下的小木屋里。有一天，它发现窗外飘起了第一片雪花，开心得转了三圈，然后轻轻说：冬天来啦，我们去堆一个圆圆的雪人吧。'''

chunks = []
for gs, ps, audio in pipe_z(text, voice='zf_xiaobei', speed=1.05):
    chunks.append(audio)
import numpy as np
wav = np.concatenate(chunks)
sf.write('child-zh.wav', wav, 24000)

女声池里我挨个听了 zf_xiaobei / zf_xiaoni / zf_xiaoxiao。小贝更亮、更像小朋友讲故事；小妮偏快偏飘；笑笑更稳，但童声感弱一点。所以儿童感中文段定 zf_xiaobei，speed=1.05 稍抬一点活泼。

英文对照另起 lang_code='a'，音色 af_sky、同样 speed=1.05。短句故事英译贴在下面，方便你对照 Ana 那路「童声感」——记住：这是逼近，不是同名音色。

Once upon a time, a little fox found the first snowflake of winter. It spun three happy circles and whispered, let's build a round snowman.

两段中间留约半秒静音，拼成终稿 child-ana-like.wav。CPU 热身后，中文段推理大约数秒，英文段更快；成片大约二十多秒可听。

核：中英 voice 名、speed、终稿文件名是否对上

核：24kHz、有能量、中英两段中间有短静音

 

—第三步：科技男声压一点语速—

科技短片旁白我要的是沉稳解说，不是广告吆喝。统一样本文本如下，口播量大约二十秒：

今天我们本地实测开源语音合成模型 Kokoro。它只有八千二百万参数，却能在普通电脑上直接出旁白。如果你在做科技短片，需要沉稳解说口播，可以先试中文男声，再按语速微调，听感接近博客评测腔。整段样音大约二十秒，方便你对照自己的脚本。

男声探针按优先级听：zm_yunyang / zm_yunxi / zm_yunjian，英文另听 am_michael / am_fenrir 作对照。终选 zm_yunyang，speed=0.95。云扬更稳、更像评测口播；云希略冲；云健顿挫偏多。英男声稳，但本稿主旁白是中文，英文只当探针，不进终稿。

pipe_z = KPipeline(lang_code='z')
text = '''今天我们本地实测开源语音合成模型 Kokoro。...'''  # 同上全文
chunks = []
for gs, ps, audio in pipe_z(text, voice='zm_yunyang', speed=0.95):
    chunks.append(audio)
sf.write('tech-blog-male.wav', np.concatenate(chunks), 24000)

核：device=cpu、FINAL 两行文件与时长

核：单段中文、振幅饱满、时长大约十八秒

所以你下次可以：先固定样本文本，再只改 voice 与 speed，听三五个就停，别在参数宇宙里迷路。

【广告位2】

 

—听感怎么说，边界怎么划—

儿童感一路：中文小贝讲雪人故事，亮、清；英文 sky 短句年轻。拼在一起能当「童声感草稿旁白」。它替不了 Azure Ana 那种神经童声的品牌完成度——标题党若写成「本机一键 Ana」，那就忽悠了。

科技男声一路：云扬降速后，听感接近科技博客口播。优点是本机、免费、改稿快；不足是中文音色训练数据官方评分本身一般，长句偶发黏连，情绪层次也薄。要极稳商品旁白、严格情绪、或童声要「像 Ana」，我仍会把 Azure 神经声 或 CosyVoice 留在候选里。

数字只记你自己机器上的：我这边 CPU 冷启动管道大约两秒多；十五到二十秒口播，热身推理大约数秒；终稿 child-ana-like.wav 约 24 秒、tech-blog-male.wav 约 18 秒，皆 24kHz。你的机器会更快或更慢，以你终端为准。

 

—适合谁，何时该停—

适合今晚就动手的人：

1. 科技短片 / 博客口播要先出草稿旁白

2. 不想先开通云 TTS、也不想脚本出本机

3. 能接受「童声感近似」，不追求 Ana 同名

4. 愿意花一小时把 Python 3.12 环境装顺

建议先停、或改用云端的人：

1. 必须品牌级童声（含 Ana）或严格情绪曲线

2. 长篇有声书、多角色戏剧对质量敏感

3. 要商用 SLA / 稳定并发，而不是单机草稿

4. 装依赖连续失败且赶工期——先用 Azure / CosyVoice 交差，再回头磨本地

 

—今晚你可以这样做—

1. 新建空目录，装 espeak-ng，用 Python 3.12 虚拟环境装 torch（CPU 也可）+ kokoro + misaki[zh]。
2. 先跑通 KPipeline(lang_code='z')，用上文狐狸故事出 zf_xiaobei。
3. 科技旁白试 zm_yunyang，speed 从 0.95 起听。
4. 需要英童声感对照，再加 af_sky；别对外宣称「等于 Ana」。
5. 听感不够稳，就停，改走 Azure / CosyVoice——本地是草稿加速器，不是唯一神器。

装通、出声、定音色，这三步今晚就能走完。敢动手的人，先听到自己的 WAV；不被忽悠的人，会把 Ana 同名和「童声感」分开写。
