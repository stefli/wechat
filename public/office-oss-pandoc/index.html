【公众号账号】

周报已经写完，表格也整理好了，临到交接，却还差一个文件格式。同事要的是能继续修改的 Word 文档，手里的稿子却是 Markdown——一种用简单符号标记标题、表格和列表的文本文件。重新复制一遍不难，难的是复制之后还得重新摆表、找图，再核一次金额。

我不想把已经做过的整理工作再做一遍。这次就拿一份自造的采购周报试试：把文本稿和配图放在一起，让 Pandoc 负责转换，再打开文档检查。不是拿真实客户材料练手，也不是给一张截图换个文件后缀。

今晚要办成的事很具体：把这份周报交成能继续改的文档。可文件生成之后，原来的表格和配图究竟跟过去了没有？我先从打开文档的那个画面说起，再把材料和操作一步步往前还原。

—先看交接时要打开的文件—

下面是这次转换出的 DOCX 文件，也就是常说的 Word 文档格式。我在 Linux 的 LibreOffice Writer 中打开验证，看到标题下接着金额表，往下是安排和插图，页面底部还有脚注。这里松一口气的地方，是不用从空白文档重新摆一遍内容。

实际打开后的文档。红框分别罩住金额表和插图；不是 Windows Microsoft Word 窗口。

先把范围说清：这次没有测试 Windows Microsoft Word，也不承诺复杂版式无损。这是一份结构简单的自造周报。能打开只是第一关，下面还要核对编号、金额、图和脚注，不能凭文件名判断完成。

—材料准备：让稿子和图片待在一起—

在“文档”里新建 采购周报 文件夹。本文命令使用 /home/laoli/Documents/采购周报/；你照做时，换成自己电脑里这个文件夹的实际位置。先用可公开的练习材料，保留原稿，不拿唯一一份正式周报试命令。

如果还没有 Markdown 稿，可以把下面这份示例完整复制进纯文本编辑器，以 UTF-8 保存为 采购周报.md。扩展名是 .md，不是 .md.txt；它仍然是文本稿，编辑器里看到井号、竖线和星号都正常。已有自己的稿子，也可以复制一份后改成这个文件名跟做。

红框是本轮使用的采购周报.md、采购进度.png；目录内其他文件是随后产生的结果，不是必备输入。

稿子中的 ![…](采购进度.png) 是图片引用，括号里的名字必须能找到对应文件。图片和稿子放同一层，后面也从这一层运行转换，就少了一次到处找附件的麻烦。表格里的竖线分隔列，短横线那一行声明表头；这两处别在复制时漏掉。

原始文本稿的实际打开画面。红框内是图片相对路径，表格、列表和脚注也都在源稿里。

—打开终端，先把 Pandoc 装好—

本次实测环境是 Linux Debian。Debian/Ubuntu 的主路是在系统终端安装软件包，需要联网和 sudo 管理员权限；没有权限就请管理员协助，不要继续粘贴转换命令。先打开系统应用菜单里的“终端”，逐行执行下面的命令。

sudo apt-get update && sudo apt-get install -y pandoc
command -v pandoc
pandoc --help

第一行更新软件包索引后安装 Pandoc，后两行确认命令能找到、帮助能显示。如果遇到网络、权限、找不到包或找不到命令的问题，先停在这里。我准备环境时也曾因软件包索引缺失安装失败，更新索引后才装上；不能把复制一行命令说成每台机器都会直接成功。

Pandoc 是开源文档转换工具，官方许可为 GPL-2.0-or-later，官方发布记录显示仍在维护。官方说它重在转换文档结构，并不保证任意复杂排版原样保留。下面写的是本次实际样本的结果，不拿官方支持列表代替逐项检查。还需准备一个能打开 DOCX 的编辑器，本轮验收使用的是系统已有的 Linux 文档编辑器。

【广告位1】

—第1步：进入放稿子的文件夹—

回到终端，先进入刚才的材料目录，再看文件是否确实存在。路径带中文没有问题，外面的引号照抄保留。只有看到采购周报.md、采购进度.png 都列出来，才继续往下；如果提示目录不存在，先回文件管理器确认位置。

cd "/home/laoli/Documents/采购周报"
ls -l 采购周报.md 采购进度.png

这一步看起来很普通，却决定图片能不能找到。命令从哪个目录执行，跟你在文件管理器里看着哪个窗口，不是同一回事。把终端位置对齐到材料目录后，再运行转换，图片的相对路径才有明确的起点。

—第2步：转成新的 DOCX 文件—

下面几行请逐行执行。转换命令后立刻运行 echo，查看刚才的退出码；非 0 先停下来读报错，别把旧文件当新结果。即使显示 0，也把终端里的 WARNING 警告读完，后面的验收不能省。输出文件使用新名字，不覆盖原来的 .md 稿。

pandoc 采购周报.md -o 采购周报.docx
echo exit:$?
wc -c 采购周报.md 采购进度.png 采购周报.docx

这里 -o 后面是输出文件名，.docx 后缀告诉 Pandoc 要生成的格式。我这次主转换 exit:0；源稿 680 B，PNG 19659 B，DOCX 28983 B。它们是本次材料的字节数，用来对照这张屏幕，不是你换一张图之后也必须得到的数。

红框是 exit:0 和三项实际大小；上方语言资源警告没有隐藏。

终端没有再要求手工指定每一段的字体和坐标。Pandoc 按源稿里的标题、表格等结构生成文档，这正是省掉重复整理的地方。但“按结构生成”也意味着，文档样式未必等于公司现成模板，不能把这个动作理解成截图级复刻。

—第3步：打开结果，逐项核对—

回到“文档”的采购周报文件夹，双击 采购周报.docx；也可以在文档编辑器点“文件 → 打开”，选这个文件。别误开同名 .md。需要改文字时，在 DOCX 正文里定位相应段落继续编辑，保存时留意编辑器对文档格式的提示。

这份样本的检查不是只看首页像不像。我逐项核对了中文标题、周报编号 WB-2026-1122、合计 1,288.00、金额表、列表、插图和脚注。结构检查也确认有表格和嵌入图片；下面这张是文档实际渲染，可对照源稿逐项查看，重点看合计行和图片图说。

真实文档渲染：红框依次对应编号、金额表、插图与图说、脚注；不是软件窗口截图。

你换自己的周报时，就查自己的编号和金额，再从表格第一行看到最后一行，核对是否缺列；向下找到图片和脚注。数字对、结构在、附件全，比“文件已经生成”更接近交接完成。正式交给同事之前，还应在实际接收方使用的编辑器里复核分页和字体。

【广告位2】

—我的经验教训：0 不等于图片齐了—

我专门留了一份缺图示例：稿子引用一张不存在的图片，再转换成另一个 DOCX。结果仍然 exit:0，也确实产生文件。这个时候如果只去文件夹里确认“有文档”，很容易以为可以结束了。

pandoc 缺图示例.md -o 缺图结果.docx
echo exit:$?

终端实际写的是 replacing image with description，意思是用描述替代图片。本次这份缺图稿 98 B，生成文档 9956 B；打开后，原图位置只有“不存在的附件”描述。它不是转换失败后完全没文件，而是文档里少了你原本要带的图。

红框完整包含缺图警告、exit:0 和98/9956字节；不是主周报那一次运行。

实际打开缺图结果，红框内是描述文字，并没有原图片。

你不必为了跟做再造一份缺图稿，记住这条就够了：见到缺图警告，先修正图片位置或文件名，再重新转换并打开核验。我以后会把稿子和插图一起整理，再看终端警告，不会把 exit:0 当附件齐全的证明。

主周报那次还有 zh-CN 翻译资源警告，提示 Table、Figure 没有定义翻译。本例打开后，已核对的中文内容和图表仍在，但这不等于警告可以一概忽略。如果你的稿子依赖自动生成的表名、图名，遇到类似提示就要专门检查这些文字，而不是凭这份简单样本直接放行。

复杂表格、公司模板、特殊字体和精细分页，本次没有覆盖。若交接要求就是严格沿用某套版式，先拿一页样稿给接收方验证；别等整份长报告转完才发现样式不合适。

—最后—

这次让我轻松下来的，不是“所有排版从此不用管”，而是已经写好的内容有了一条继续交接的路：稿子和图放一起，转成 DOCX，再把关键位置核一遍。省下重新摆表找图的功夫，留给真正需要改的内容。
