【公众号账号】

一提银行对账，很多人默认「人对人、格子对格子」。其实卡点常常是：流水 CSV 一份、发票清单一份，两边金额对不上时，差额被悄悄并进「已匹配」。今晚用 DeepSeek Harness 做一次 AI办公对账——差额必须显式列出。

常见误判是：模型说「基本对上了」就完事。真要的是三栏：仅流水有、仅发票有、金额差。DeepSeek 在这里不是替出纳签字，是把漏项摊开。

分两层看：材料怎么摆，提示词怎么锁；再看本机差额表能不能验收。

 

—先分清流水和发票各说什么—

因为两边字段名不一样，所以先别急着扔进会话。流水侧：日期、对手方、金额、摘要；发票侧：发票号、供应商、金额、开票日。匹配键我用「对手方 + 金额绝对值」，金额差单独成行。

图：银行流水 CSV 节选（示例对手方）；对账前先确认字段。

  • 回款行（正数）也可能要对照收款类单据，别只盯支出。
  • 补差、尾款这种摘要，最容易和发票金额差几十、几百。
  • 示例材料放在我的文档示例目录，路径对外写 laoli 虚拟用户。

【广告位1】

 

—提示词把「差额」写成硬字段—

官方能做的是读文件与列表；我读下来关键是禁止静默抹平。提示词里把输出列写死，模型就不容易用一句「已对齐」糊弄过去。

对照 bank_flow_oct.csv 与 invoices_oct.csv。
按对手方+金额绝对值匹配。
列出差额：仅流水有 / 仅发票有 / 金额差。
差额表字段：类型、对手方、流水金额、发票金额、差额、备注。
数字只引用文件；差额必须显式列出，禁止静默并进已匹配。

图：DeepSeek Harness 桌面真窗主区（已裁会话列）；红框罩差额汇总。

红线：差额必须显式列出，不要让「基本匹配」替代表格。

 

—差额表怎么验收—

本机示例跑完：供应商甲 12800、供应商丙 6400、客户乙 35600 能对上；仅流水有——客户丁 9200、供应商甲补差 3200；金额差——发票 3500 对流水补差 3200，差 300。所以你下次可以：先收「仅流水/仅发票」两堆，再处理金额差。

图：银行对账差额表；红框罩住三类差额行。

  1. 核对：每个差额行能否在原 CSV 找到出处。
  2. 核对：已匹配行不要再出现在差额表。
  3. 停手：模型开始「建议调账分录」且给不出凭证号——那是会计活，不是这篇的范围。

【广告位2】

 

—能做 / 不能做—

能做：银行对账差额清单、加速找漏。不能做：自动生成合法记账凭证、对接网银企业版、声称零差错。DeepSeek Harness 是桌面 Agent，边界就停在「表」这一层。

因为对账最怕「看起来齐了」，所以验收时我习惯把差额表另存一份，和财务同事对齐时只讨论显式差额行，不讨论模型的形容词。AI办公提速的是找漏，不是替人签字；这一句要写进自己的操作习惯里。

若流水来自不同银行导出，字段名可能叫「交易金额」或「发生额」——提示词里用你文件真实列名替换示例列名，再跑一遍。口径不变，列名跟着文件走。

 

—最后—

结论钉在口径：用 DeepSeek / DeepSeek Harness 做 AI办公式银行对账时，差额三栏写进提示词，验收看表不看形容词。

适合每月要对一截流水的岗位；不适合把 Agent 当财务系统。材料普通，口径写清就能复跑。
